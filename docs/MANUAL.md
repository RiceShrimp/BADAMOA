## 1. 처음 시작

관리자 계정을 만들고 로그인하면 바로 씁니다. 처음 설치한 Hub에는 연습용 샘플이 들어 있습니다.

### 1.1 첫 실행과 로그인

- **첫 실행**: 계정이 하나도 없으면 "관리자 계정 만들기"가 나옵니다. 아이디(기본 `admin`)와 8자 이상의 비밀번호를 정하면 그 계정이 관리자가 됩니다.
- **샘플 (COCO8)**: 처음 관리자 계정을 만들면 "샘플 (COCO8)" 프로젝트가 생깁니다.
  - COCO8 검출 · 분할 · 키포인트(17점) 데이터셋
  - **COCO8 검수 예시**: 일부러 틀린 라벨(같은 물체에 박스 둘, 아주 작은 박스, 이미지를 덮는 박스, 한 물체에 클래스 둘, 라벨 안 한 이미지)을 넣은 검출 버전
  - 인터넷 없이 되고, 필요 없으면 프로젝트를 지우면 됩니다. 이미 쓰던 Hub에는 넣지 않습니다.
- **로그인**: 이 Hub의 주소(예: `http://192.168.106.2:8470`)를 브라우저로 엽니다. 로그인은 14일 동안 유지됩니다.

### 1.2 역할

| 역할 | 할 수 있는 것 |
|---|---|
| 멤버 | 데이터셋 · 라벨링 · 학습 · 모델을 씁니다 |
| 관리자 | 멤버가 하는 일에 더해 서버 추가 · 사용자 관리 · 모델 종류 올리기 같은 관리 |

### 1.3 화면 구성

| 자리 | 내용 |
|---|---|
| 왼쪽 메뉴 | **Build**(데이터셋) · **Annotate**(라벨링 · 검수) · **Develop**(학습 · 모델) · **Management**(노드 · 작업 · 에이전트 · 설정) · 휴지통. 회색으로 "P2 · P3 …"가 붙은 칸은 다음 단계에 생길 기능입니다 |
| 위쪽 줄 | 지금 위치, 데이터셋 등록 진행("등록 중 N"), 접속 중인 사람("접속 N명", 관리자), 노드 상태("노드 2/2 온라인"), **설명서**, 버전 표시(누르면 릴리즈 노트), 밝은 · 어두운 테마 |
| 왼쪽 아래 | 내 계정(비밀번호 바꾸기)과 로그아웃 |

**접속 중인 사람**(관리자): 위쪽의 "접속 N명"을 누르면 최근 3분 안에 화면을 열어 두었거나 API · MCP로 쓴 사람이 나옵니다. 사람마다 역할, 마지막 활동, 웹 세션 · API 토큰 수, 접속한 IP가 보입니다.

### 1.4 카드 순서 바꾸기

데이터셋 · 라벨링 · 검수 · 학습 · 모델의 카드와 노드 목록은 순서를 바꿀 수 있습니다.

1. 이름 옆의 점 손잡이(⠿)를 잡고 끕니다. 키보드로는 손잡이에서 스페이스 → 화살표 → 스페이스.
2. 되돌리려면 화면 오른쪽 위의 **원래 순서로**를 누릅니다.

순서는 사람마다 Hub에 남아 다른 PC에서도 같고, 다른 사람의 화면은 바뀌지 않습니다.

### 1.5 Hub가 새 버전으로 바뀌면

화면 위에 "MOA가 업데이트되었습니다 … 새로고침"이 나옵니다. 누르면 새 화면을 씁니다.

## 2. 홈

Hub 전체를 한눈에 봅니다.

- **숫자**: 프로젝트 · 데이터셋 · 이미지 · 모델 · 온라인 노드 · 저장 공간.
- **시작하기**: 원격 서버 추가 → 첫 데이터셋 가져오기 → 첫 학습 → 에이전트 연결. 다 하면 사라집니다.
- **최근**: 최근 프로젝트 · 최근 학습 · 최근 활동(누가 무엇을 했는지) · 최근 작업.

## 3. 데이터셋

이미지는 복사하지 않고 제자리에서 등록하고, 한 번 만들면 바뀌지 않는 버전으로 관리합니다.

### 3.1 프로젝트

프로젝트는 같은 클래스 체계를 쓰는 데이터셋 · 학습 · 모델을 묶는 단위입니다. 첫 화면은 프로젝트 카드(대표 이미지 · 태스크 · 데이터셋 · 버전 · 이미지 · 학습 · 모델 수)입니다.

| 하는 일 | 방법 |
|---|---|
| 새 프로젝트 | 오른쪽 위 버튼. 이름 · 폴더 · 설명을 적습니다 |
| 폴더로 나눠 보기 | 프로젝트가 많아지면 폴더 칩으로 나눠 봅니다 |
| 이름 · 폴더 · 설명 바꾸기 | 카드의 설정 버튼 |
| 거르기 | 태스크와 클래스 이름(예: "person이 있는 프로젝트") |
| 정렬 | 최근 수정 · 이름 · 이미지 수 · 내가 끌어 놓은 순서 |
| 열기 | 프로젝트를 누르면 그 안의 데이터셋 카드가 보입니다 |

### 3.2 데이터셋 가져오기

이미지는 **노드(서버)에 있는 폴더를 복사하지 않고 그 자리에서 등록**합니다. Hub에는 썸네일과 라벨만 들어갑니다.

1. 프로젝트 화면에서 **데이터셋 가져오기**를 누릅니다.
2. **노드**: 이미지가 있는 서버를 고르고, 폴더를 찾아 들어가 고릅니다. 경로를 직접 적어도 됩니다.
3. **데이터셋 이름 · 버전 이름**(예: `street`, `v1`)과 메모를 적습니다. 같은 데이터셋 이름으로 가져오면 그 데이터셋의 새 버전이 됩니다.
4. **형식**: 자동 감지 · YOLO · COCO · 클래스별 폴더.
5. **태스크**: 비워 두면 폴더를 보고 정합니다(아래 표). 팀이 정한 태스크 이름(예: OCR)도 쓸 수 있습니다.
6. **라벨이 없는 이미지**(접힌 칸): 어떻게 다룰지 고릅니다(아래 표). 이미지만 있는 폴더라면 쓸 **클래스 이름**을 적습니다.
7. **가져오기**를 누릅니다. 창을 닫아도 등록은 계속됩니다.

| 폴더에 있는 것 | 정해지는 태스크 |
|---|---|
| 클래스별 폴더 | 분류 |
| `kpt_shape` · keypoints | 키포인트 |
| 윤곽 | 분할 |
| 그 밖 | 검출 |

| 라벨이 없는 이미지 | 뜻 |
|---|---|
| 자동 | 폴더에 라벨 파일이 하나도 없으면 "아직 안 함", 아니면 "배경" |
| 배경 | 찾을 물체가 없는 이미지 |
| 아직 안 함 | 라벨할 이미지 |

#### 등록 진행

위쪽 "등록 중"과 프로젝트 화면의 카드에서 진행을 봅니다. 등록은 세 단계로 갑니다.

| 단계 | 보이는 것 |
|---|---|
| 1. 이미지 찾기 | 찾은 장수, 초당 N장 |
| 2. 라벨 읽기 | % · 남은 시간, 초당 N개 |
| 3. 이미지 읽고 등록 | 장수 · % · 읽은 용량 · 남은 시간, 초당 N장 · MB/s |

- 마지막 단계에서 들어온 이미지부터 바로 볼 수 있습니다.
- 수십만 장 · 수백 GB면 마지막 단계가 가장 오래 걸립니다(이미지를 모두 한 번 읽어 지문과 썸네일을 만듦).
- 속도와 남은 시간은 최근 1분의 빠르기로 셉니다.
- Hub 디스크에 썸네일 · 기록이 들어갈 자리가 없으면(디스크의 2% 또는 2 GB는 늘 남김) 필요한 양과 남은 양을 알리고 멈춥니다.

#### 멈추기

등록이 차례를 기다리는 중이면 **취소**, 읽는 중이면 **중지**를 누릅니다. 버튼은 위쪽 "등록 중" 칸, 프로젝트 화면의 카드, 가져오기 창, 버전 화면의 "등록 중" 줄에 있습니다.

멈춘 등록은 아무것도 남기지 않으므로 같은 이름으로 다시 가져올 수 있습니다.

#### 일시정지 · 이어하기

이미지를 읽는 중(3단계)이면 **중지** 옆의 **일시정지**로 지금까지 등록한 것을 남긴 채 멈출 수 있습니다. 큰 데이터셋을 잠시 멈췄다가 이어 갈 때 씁니다.

- 일시정지한 등록은 위쪽 칸에 "등록 일시정지"로 남고, "3,600 / 31,000장 등록함"처럼 어디까지 했는지 보입니다.
- **이어하기**: 같은 서버에서 같은 버전으로 이어 갑니다. 서버는 폴더를 다시 훑되, 이미 등록한 파일은 읽지 않고 나머지만 읽습니다(로그에 "이미 등록된 N장은 건너뛰고 M장을 읽습니다").
- **버리기**: 지금까지 등록한 것을 지웁니다. 중지한 등록처럼 같은 이름을 다시 쓸 수 있습니다.
- 이어 하던 등록이 실패해도 다시 일시정지 상태로 남아, 이어하기를 다시 누를 수 있습니다.

### 3.3 버전 화면

데이터셋 카드를 누르면 그 데이터셋의 최신 버전이 열립니다.

> [!NOTE]
> 버전은 한 번 만들어지면 바뀌지 않습니다(이미지마다 split과 라벨이 고정). 그래서 학습한 모델이 정확히 어떤 데이터로 배웠는지 늘 알 수 있습니다.

**이름 바꾸기**: 제목 옆 **연필**로 데이터셋 이름(그 데이터셋의 모든 버전)과 버전 이름을 바꿉니다. 내용은 그대로이고 학습 · 모델도 같은 버전을 가리킵니다. 프로젝트를 만든 사람이나 관리자가 바꿉니다.

| 탭 | 내용 |
|---|---|
| **이미지** | 썸네일 그리드와 거르기(아래) |
| **클래스** | 클래스별 박스 · 이미지 수, 색, 클래스 찾기 |
| **통계** | split과 라벨 상태, 클래스, 이미지 크기, 박스가 놓인 곳과 크기 |
| **모델** | 이 버전으로 학습한 모델, 이 버전으로 평가한 모델 비교 |
| **버전** | 이 데이터셋의 다른 버전들과 비교 |

#### 거르기와 정렬

- **거르기**: split · 라벨 상태(라벨 있음 · 배경 · 아직 안 함) · 클래스 · 파일 이름 검색. 사이트 · 카메라 값이 있는 버전이면 그 칸도 나옵니다.
- **라벨 의심 순**: 모델로 평가한 적이 있으면 모델과 어긋나는 이미지부터 정렬합니다.
- **예측**: 도구 모음의 **예측**에서 실행(평가 · 오토라벨) 하나를 고르면 그 예측이 썸네일 위에 점선으로 겹칩니다.

#### 버튼

| 버튼 | 하는 일 |
|---|---|
| **새 버전** | 이 버전의 이미지를 골라 새 버전을 만들거나, split을 다시 나누거나("같은 카메라끼리" 묶어 나누기 포함), 클래스 이름을 바꾸거나 합치거나 뺍니다 |
| **내려받기** | YOLO · COCO · 클래스별 폴더 zip. 받는 링크는 일주일 동안 유지됩니다 |
| **이 버전으로 학습** | 학습 화면의 "새 학습" 창이 이 버전으로 열립니다 |
| **라벨링 묶음 만들기** | 지금 거른 이미지를 일감으로 나눠 사람에게 맡깁니다([6장](#6-라벨링)) |
| **버전 지문** | 버전 이름 옆의 12자(예: `3f9a1c2b7d04`). 내용으로 만든 지문이라 내용이 같으면 지문도 같습니다. 누르면 전체가 복사됩니다 |
| **이 버전이 있는 서버** | 등록한 원본 폴더와, 이 버전의 이미지를 받아 둔 다른 서버(폴더 · 크기 · 마지막으로 쓴 때). 받아 둔 사본은 거기서 지울 수 있습니다 |

## 4. 이미지 보기와 라벨 고치기

그리드의 썸네일을 누르면 큰 이미지와 오른쪽 칸이 열립니다. ← → 로 넘기고 Esc로 닫습니다.

### 4.1 오른쪽 칸

| 칸 | 내용 |
|---|---|
| **표시** | 라벨(L) · 클래스 이름(N) · 박스 채우기(F) 스위치, 클래스 칩(누르면 그 클래스만 끄고 켬, 모두 · 없음) |
| **라벨 N개** | 라벨마다 한 줄: 클래스와 클래스 안의 번호(위에서 아래, 왼쪽에서 오른쪽 순), 놓인 곳(왼쪽 위 · 가운데 …), 크기(픽셀) |
| **버전별 라벨** | 이 이미지의 라벨 기록(가져올 때 · 사람이 고친 것 · 모델이 그린 것). 두 기록을 나란히 비교할 수 있습니다 |
| **이미지** | 크기 · split · sha256 · 경로 등 |

**라벨 목록 다루기**

- 줄에 마우스를 올리면 그 라벨이 이미지에서 **깜박이고** 나머지는 흐려집니다. 누르면 계속 깜박이고, 다시 누르면 풀립니다.
- 눈 버튼으로 그 라벨만 끄고 켭니다. "끈 N개 다시 보이기"로 한꺼번에 되돌립니다.

**확대 · 이동**: 마우스 휠로 확대, 끌어서 이동(고치는 중에는 가운데 버튼이나 스페이스를 누른 채 끌기), 0으로 맞추기.

### 4.2 라벨 고치기

**라벨 고치기**(E)를 누르면 같은 화면이 편집 상태가 됩니다.

> [!NOTE]
> 고치기는 **최신 버전과 작업 중**에서만 됩니다. 오래된 버전에는 "최신 버전에서 고치기" 버튼이 나옵니다.

| 하는 일 | 방법 |
|---|---|
| 고르기 · 그리기 | 고르기(V) · 박스 그리기(B, 끌어서). 분할은 윤곽 그리기(점을 찍고 Enter로 닫기), 키포인트는 점 목록에서 고른 점을 찍기 |
| 클래스 | 고른 라벨의 클래스를 오른쪽 목록에서 고르거나 숫자키 1~9 |
| 옮기기 · 크기 | 고른 라벨을 끌거나 모서리를 끌기. 윤곽 · 점은 점을 끌기 |
| 지우기 | Delete (윤곽은 고른 점만 지울 수도 있음) |
| 배경으로 | 라벨을 모두 지우고 "찾을 것이 없는 이미지"로 |
| 되돌리기 · 다시 | Ctrl+Z · Ctrl+Shift+Z |
| 복사 · 붙여넣기 | Ctrl+C · Ctrl+V |
| 저장 | Ctrl+S. ← → 로 넘기면 저장하고 넘어감. 저장하지 않고 나가려면 Esc |
| 라벨 목록 | 줄을 누르면 그 라벨이 골라짐 |

**저장하면**

- 고친 라벨은 **작업 중**([5장](#5-작업-중과-버전으로-확정))에 들어가고, 지금 보던 버전은 그대로 남습니다.
- 다른 사람이 같은 이미지를 먼저 고쳤으면 "다른 사람이 먼저 고쳤습니다"가 나옵니다. 그 라벨을 보거나 내 것으로 저장할지 고릅니다.

### 4.3 모델 예측 겹쳐 보기

이 이미지를 예측한 실행(평가 · 오토라벨)이 모두 나옵니다. 모델 이름 · 버전, 평가(split) 또는 오토라벨(묶음 이름), 날짜로 구분합니다.

1. 실행을 셋까지 골라 켭니다. 라벨(실선) 위에 실행마다 다른 점선과 글자(A · B · C)로 겹쳐 그립니다.
2. **확신도** 막대로 몇 % 이상만 볼지 정합니다.
3. 라벨에 없는 예측은 "라벨로 넣기"로 바로 채웁니다.

- 켜고 끄기는 **P**입니다.
- 고른 실행과 확신도는 다음 이미지에서도 그대로입니다.
- 오토라벨에서 확신도가 높아 바로 들어간 라벨에는 "모델이 그린 것, 아직 사람이 확인하지 않음"이 붙습니다. 고치면 사람이 고친 라벨이 됩니다.

## 5. 작업 중과 버전으로 확정

git으로 치면 버전은 커밋, **작업 중**은 커밋 전 변경, **버전으로 확정**은 커밋입니다.

### 5.1 작업 중

- 데이터셋마다 작업 중은 하나입니다. 처음 라벨을 고쳐 저장하면 생기고(바탕 = 그때의 최신 버전), 확정하거나 모두 되돌리면 사라집니다.
- 데이터셋 트리와 버전 화면에 **작업 중 · 고친 것 N**으로 보입니다. 열면 버전 화면과 같은 화면이고, 거기서 계속 고칩니다.
- 작업 중인 동안 다른 길로 새 버전이 생기면, 작업 중의 바탕을 그 버전으로 옮길지 묻습니다.

### 5.2 바뀐 내용 보기

**바뀐 내용** 카드는 바탕 버전과 비교해 보여 줍니다.

- 라벨 추가 · 지움 · 옮김 · 클래스 바뀜 수, 클래스가 어떻게 바뀌었는지, 상태가 바뀐 이미지, 고친 사람.
- 종류를 누르면 그렇게 바뀐 이미지만 그리드에 나옵니다.
- 썸네일에는 "+1 −1 ⤢1 ⇄1"이 붙습니다. 이미지 보기의 "바뀐 것 보기"(D)는 바탕 버전과 겹쳐 보여 줍니다.

### 5.3 확정하거나 되돌리기

| 버튼 | 하는 일 |
|---|---|
| **버전으로 확정** | 이름과 메모를 적으면 새 버전이 됩니다. 바뀐 내용과 그때의 검수 기록이 함께 남습니다 |
| **모두 되돌리기** | 작업 중을 지웁니다. 고친 라벨은 이미지의 라벨 기록에 남습니다 |

> [!IMPORTANT]
> 작업 중은 학습 · 내보내기 · 평가에 쓸 수 없습니다(확정하지 않은 것은 바뀔 수 있으므로). 바탕 버전으로 학습을 시작하면 "작업 중에 고친 이미지 N장은 아직 이 버전에 없습니다"를 알려 줍니다.

## 6. 라벨링

라벨링 묶음은 라벨할 이미지를 **일감**으로 나눠 사람에게 맡기고, 라벨링 → 검수 → 완료로 따라가는 단위입니다. 라벨은 데이터셋의 작업 중에 모였다가 "버전으로 확정"하면 새 버전이 됩니다.

### 6.1 첫 화면

- **내 일감**: 나에게 맡겨진 일감과 남은 수. **이어서 라벨링**(남은 장 수, 돌려받은 수) · **검수** 버튼으로 바로 엽니다.
- **프로젝트별 묶음 카드**: 대표 이미지, 진행 막대(승인 · 라벨함 · 돌려받음 · 할 일), 보드 칸별 일감 수. 오토라벨이 도는 묶음에는 "오토라벨 중"이 붙습니다.

### 6.2 묶음 만들기

1. 데이터셋의 **최신 버전이나 작업 중**에서 이미지를 거릅니다(예: 라벨 상태 "아직 안 함"). 검수 화면에서 찾은 이미지로 만들 수도 있습니다([8장](#8-검수)).
2. **라벨링 묶음 만들기**를 누르고 적습니다.
   - 이름
   - 지시문(라벨링하는 사람에게 보임)
   - 일감 하나에 이미지 수(기본 50)
   - **검수하기**: 승인 · 돌려보내기를 할지
3. 만들어지면 보드가 열립니다. 맡길 사람은 보드에서 정합니다.

### 6.3 보드

| 칸 | 뜻 |
|---|---|
| 미배정 | 아직 맡은 사람이 없는 일감 |
| 라벨링 | 라벨링하는 중이거나 돌려받은 이미지가 있는 일감 |
| 검수 | 다 라벨링해서 검수를 기다리는 일감 (검수하는 묶음만) |
| 완료 | 모두 승인된 일감 (검수 없는 묶음은 모두 라벨링된 일감) |

- 일감 카드에서 **라벨링할 사람 · 검수할 사람**을 고릅니다. "내 일감만"으로 내 것만 봅니다.
- **라벨링** · **검수** 버튼으로 그 일감의 이미지를 엽니다.
- 머리말에 지시문, 이미지 수와 상태별 수, (돌렸다면) 오토라벨 결과가 보입니다.

### 6.4 라벨링하기 · 검수하기

| 하는 일 | 방법 |
|---|---|
| **라벨링** | 일감의 이미지가 처음부터 편집 상태로 열립니다. 고친 뒤 **완료하고 다음**(Enter). 고칠 것이 없으면 그대로 완료해도 "라벨함"이 됩니다. 돌려받은 이미지에는 검수자의 메모가 보입니다 |
| **검수** | 라벨링된 이미지를 보고 **승인**하거나, 이유를 적어 **돌려보내기**. 돌려보낸 이미지는 라벨링 칸으로 돌아갑니다 |

다 끝나면 데이터셋의 작업 중을 **버전으로 확정**합니다([5장](#5-작업-중과-버전으로-확정)).

## 7. 오토라벨

등록한 모델이 묶음의 이미지에 라벨을 **먼저 그립니다**. 라벨링하는 사람은 처음부터 그리지 않고 모델이 그린 것을 고칩니다.

### 7.1 오토라벨 돌리기

1. 묶음 보드 오른쪽 위의 **오토라벨**을 누릅니다.
2. **모델**을 고릅니다.
   - 같은 프로젝트의 모델 중 태스크가 같고 클래스가 이름으로 맞는 것이 나옵니다(별칭이 붙은 것, 지표가 좋은 것 먼저).
   - 쓸 수 없는 모델은 이유와 함께 흐리게 보입니다.
   - 이 데이터셋에 없는 모델의 클래스는 버립니다.
3. **최소 확신도**(기본 0.25): 이보다 낮은 예측은 버립니다.
4. **자동 승인**(골라서 켬): 예측이 모두 이 확신도(예: 0.8) 이상인 이미지는 바로 작업 중에 저장해 검수로(검수 없는 묶음은 완료로) 보냅니다. 예측이 하나도 없는 이미지는 사람이 보도록 남깁니다.
5. **오토라벨 시작**을 누릅니다. 이미지가 있는 서버에서, GPU가 있으면 GPU로 돕니다. 묶음 머리말에 진행과 결과(예측한 이미지 · 라벨 수 · 자동 승인 · 예측 없음)가 나옵니다.

### 7.2 라벨링할 때

아직 안 한 이미지를 열면 에디터가 **모델이 그린 라벨에서 시작**합니다("○○이 그린 라벨 N개에서 시작합니다", "모두 지우고 처음부터").

- 고쳐 저장해야 작업 중에 들어갑니다.
- 사람이 이미 라벨링했거나 돌려받은 이미지는 건드리지 않습니다.

> [!NOTE]
> - 오토라벨을 돌릴 서버는 **오토라벨용** 역할이 있어야 하고([11장](#11-노드서버)), 노드 프로그램이 0.52.0 이상이어야 합니다.
> - 오토라벨은 그 모델 종류가 오토라벨을 지원할 때만 쓸 수 있습니다. 내장 모델 종류(Ultralytics YOLO · torchvision, 네 작업 모두)는 지원합니다.

## 8. 검수

라벨이 빠졌거나(미라벨) 틀렸을(오라벨) 이미지를 찾습니다. 모델 없이 바로 되는 **규칙 검사**와, 평가한 모델로 하는 **모델 기준** 검사가 있습니다.

### 8.1 첫 화면

학습 · 모델처럼 프로젝트가 카드로 나옵니다(폴더가 여럿이면 폴더로 거릅니다).

- **프로젝트 카드**: 데이터셋들의 최신 라벨(작업 중이 있으면 작업 중)에서 찾은 미라벨 · 오라벨 · 박스 오류 수를 더한 것과, 데이터셋마다 걸린 이미지 수. 문제가 많은 프로젝트가 먼저 나옵니다.
- **데이터셋 카드**: 프로젝트를 누르면 나옵니다. 미라벨 · 오라벨 · 박스 오류, 그리고 평가한 모델이 있으면 모델 기준 수. 문제가 많은 데이터셋이 먼저입니다.
- 데이터셋 카드(또는 프로젝트 카드의 데이터셋 줄)를 누르면 그 버전의 검수 화면이 열립니다. 위의 **버전**에서 그 데이터셋의 작업 중 · 다른 버전을 고릅니다.
- 검수 화면의 **데이터셋에서 보기**로 이 버전을 데이터셋 탭에서 엽니다.
- 아주 큰 버전은 처음 열 때 검사합니다.

### 8.2 검사 종류

| 갈래 | 규칙 검사 (모델 없이 바로) | 모델 기준 (평가한 모델이 있을 때) |
|---|---|---|
| 미라벨 | 라벨 안 한 이미지 | 라벨에 없는 물체 |
| 오라벨 | 한 물체에 클래스 둘, 드문 클래스(두 번 이하) | 클래스가 다를 수 있는 라벨, 모델이 못 찾은 라벨 |
| 박스 오류 | 같은 물체에 박스 둘(IoU 0.95 이상), 아주 작은 박스(3픽셀 미만), 이미지를 거의 덮는 박스(98% 이상) | — |

모델 기준 카드가 무엇을 세는지는 [8.3](#83-모델-기준)에 있습니다.

**박스 검사의 임계값**: 한 물체에 클래스 둘 · 같은 물체에 박스 둘 · 아주 작은 박스 · 이미지를 거의 덮는 박스 카드의 오른쪽 위 **톱니**를 누르면 임계값 창이 뜹니다.

- 막대로 IoU · 픽셀 · 넓이 비율을 바꾸면 카드 · 이미지 목록 · 노란 테두리가 바로 그 값으로 다시 셉니다.
- 창에 임계값별 이미지 수가 함께 나오고, 칸을 누르면 그 값으로 바뀝니다. 바꾼 카드는 톱니가 강조색으로 보입니다.
- **기본값으로**로 되돌립니다.

> [!NOTE]
> 임계값은 지금 보는 검수 화면에서만 바뀝니다. 다른 사람의 검수 · 보드 · 라벨링 묶음은 기본값 그대로입니다. 모델 기준의 임계값([8.3](#83-모델-기준))도 같습니다.

### 8.3 모델 기준

**모델 기준 고르기**: 이 버전에 맞는(같은 태스크 · 클래스) 평가가 있으면 고를 수 있고, 어느 모델 · 언제 평가했는지가 보입니다. 평가는 모델 화면에서 합니다([10장](#10-모델)).

**세는 방식**: Hub가 저장된 예측으로 FiftyOne(compute_mistakenness)처럼 셉니다. 예측과 라벨을 클래스와 상관없이 상자로 짝짓고(IoU 0.5, 확신도 높은 것부터), 모델이 확신하는 것만 셉니다. 평가를 다시 돌릴 필요는 없습니다.

| 카드 | 갈래 | 걸리는 것 (기본값) |
|---|---|---|
| **라벨에 없는 물체** | 미라벨 | 짝이 되는 라벨이 없는 예측(확신도 0.95 초과) |
| **클래스가 다를 수 있는 라벨** | 오라벨 | 짝지어진 라벨의 클래스가 예측과 다름(확신도 0.95 초과) |
| **모델이 못 찾은 라벨** | 오라벨 | 어떤 예측도 닿지 않고(IoU 0.1 미만) 이미지의 0.1% 이상인 라벨 |

**모델 기준의 임계값**: 검수 화면에서 확신도(0.25~0.99)와 못 찾은 라벨의 최소 크기를 누구나 바로 바꿉니다.

- 바꾸면 카드 · 이미지 목록 · 노란 테두리가 그 자리에서 다시 셉니다.
- 단계별 이미지 수 표(확신도 0.5~0.99, 크기 0~2%)로 임계값에 따라 무엇이 달라지는지 보고, 칸을 누르면 그 값으로 바뀝니다.
- **FiftyOne 기본값으로**로 되돌립니다.

**모델로 검사하기**

1. **모델**을 고릅니다. 이 데이터셋으로 학습한 모델 말고도, 태스크가 같고 이 버전에 모델의 클래스가 모두 있으면(이름으로 맞춤) 다른 버전 · 다른 데이터셋 · 다른 프로젝트의 모델도 나옵니다. 모델마다 무엇으로 학습했는지 보입니다.
2. **평가할 부분**(train · val · test)을 고릅니다. 여럿 고르면 한 기준으로 모입니다.
3. **검사할 서버**를 고릅니다. 기본은 이미지가 있는 서버이고, 다른 서버는 이미지를 먼저 받습니다.

> [!WARNING]
> 다른 데이터로 학습한 모델은 라벨 기준이나 촬영 환경이 다르면 모델의 잘못이 미라벨 · 오라벨로 더 많이 잡힐 수 있습니다. 걸린 이미지를 직접 보고 판단하세요. 이 데이터셋의 다른 버전으로 학습한 모델은 같은 이미지의 라벨을 외웠을 수 있습니다. 모델이 이 버전의 클래스 일부만 알면 그 클래스만 검사합니다.

**검사 작업 기록**: 모델 기준 칸 아래에 이 데이터셋(같은 클래스의 버전들)의 모델 검사가 끝난 뒤에도 남습니다. 줄마다 보이는 것:

- 결과(성공 · 실패 · 멈춤), 모델, 버전 · split, 돈 서버, 걸린 시간, 시작한 사람
- 이미지를 그 서버에 먼저 보냈으면 그 결과, 실패 이유, 다른 버전의 코드로 돌았으면 그 버전
- **로그**: 그 자리에서 엽니다(돌고 있으면 따라감)
- **평가 화면**: 클래스별 결과와 다시 실행

가장 최근 검사가 실패하면 그 이유가 칸에 계속 보입니다.

### 8.4 걸린 이미지 보기

검사 카드를 누르면 걸린 이미지가 나옵니다.

- **거르기**: split · 라벨 상태 · 클래스 · 사이트 · 카메라 · 파일 이름. 거른 채로 이미지 보기와 라벨링 묶음 만들기를 합니다.
- **클래스 거르기**는 여럿을 함께 고르고, 고른 클래스의 **라벨이 걸린** 이미지만 보입니다(데이터셋 화면의 클래스 거르기는 그 클래스가 들어 있는 이미지).
- 썸네일의 박스는 거르기 줄 옆의 **라벨**로 끕니다.

이미지 보기에서는 걸린 라벨이 **노란 테두리와 번호**로 보입니다. 모델 검사 카드에서 연 이미지는 테두리에 이유가 붙습니다(못 찾은 라벨: "모델이 아무것도 찾지 못한 자리", 클래스 다름: "car → 모델 truck 0.97").

- 테두리가 가리면 오른쪽 **표시**의 **검수 표시**(Q)로 모두, 검수 목록 줄의 눈 아이콘으로 하나씩 끄고 켭니다.
- 검수 목록 줄에 마우스를 올리면 그 테두리가 어디인지 또렷해집니다.
- 검수 목록 줄을 누르면 아래 라벨 목록에서 그 라벨이 골라집니다(다시 누르면 풀림). 라벨 목록에는 걸린 라벨에 "검수 N"이 붙습니다.

### 8.5 확인한 뒤

| 할 일 | 방법 |
|---|---|
| 라벨이 맞음 | **문제 없음**으로 둡니다. 라벨이 그대로인 동안 다음 버전에서도 다시 걸리지 않습니다 |
| 바로 고침 | 이미지 보기에서 **라벨 고치기**(E) |
| 사람에게 맡김 | **라벨링 묶음으로 만들기**: 찾은 이미지를 일감으로 나눠 맡깁니다 |

작업 중을 버전으로 확정하면 그때의 검수 기록(검수 전 · 후 문제 수, 고친 것, 문제 없음, 모델 기준, 검수한 사람)이 그 버전에 남습니다.

## 9. 학습

데이터셋 버전과 모델 종류를 골라 서버의 GPU에서 학습하고, 실행끼리 지표를 비교합니다.

### 9.1 첫 화면

- **위쪽 숫자**: 실행 중(대기 N) · 쓰는 GPU · 성공 · 실패.
- **지금 도는 학습**: 학습마다 진행(epoch · %), 남은 시간, 서버와 GPU, 지금까지의 지표. 기다리는 학습은 기다리는 이유가 보입니다.
- **프로젝트 카드**: 학습 · 성공 · 실패 수, 최고 지표와 최근 12번의 추이, 최근 학습 4개. 누르면 그 프로젝트의 학습 표가 열립니다.

### 9.2 학습 표

- **위쪽**: 실행 중 · 완료 · 최고 지표 · 등록된 모델, 프로젝트 고르기, **새 학습**.
- **표**: 실행 이름 · 상태 · 주요 지표 · 모델 · 노드 · 소요 · 시작.
  - 열 제목을 눌러 정렬합니다.
  - **열 고르기**로 지표 · 설정 · 정보 열을 고릅니다.
  - **CSV로 받기**로 모든 지표와 설정을 받습니다.
- **곡선 비교**: 체크한 실행(최대 8개, 기본은 최근 4개)의 지표 곡선을 위에서 겹쳐 봅니다.
- **찾기**: 이름 · 메모 · 태그로 찾고, 태그 칩으로 거릅니다.

### 9.3 새 학습

1. **버전**: 등록이 끝난 버전만 나옵니다.
2. **모델 종류**: 그 태스크를 학습하는 모델 종류가 여럿일 때만 나옵니다.
   - 기본 제공은 "Ultralytics YOLO"와 "torchvision" 둘이고, 둘 다 검출 · 분할 · 분류 · 키포인트를 합니다.
   - 모델 목록은 고른 데이터셋의 태스크에 맞춰 나옵니다(분할이면 `yolo11n-seg.pt`, Mask R-CNN …).
   - 처음 고르는 것은 검출 · 분할 · 키포인트는 YOLO, 분류는 torchvision이고, 프로젝트 기본값은 설정에서 정합니다.
3. **모델**: 예를 들어 YOLO는 yolo11n~x 등. epoch 같은 나머지 설정은 세부 설정에 있습니다.
4. **학습할 노드**: 기본은 "자동 — 이미지가 있는 서버"입니다.
   - 직접 고르면 서버마다 "이미지 있음 · 받아 둠 · 받아야 함 N GB"가 보입니다.
   - 이미지가 없는 서버를 고르면 그 서버가 먼저 이미지를 받은 뒤 학습합니다(받는 동안 GPU는 잡지 않음). 끝난 뒤 받은 데이터를 **남겨 두기 · 지우기**를 고릅니다.
5. **GPU**: 학습할 서버가 하나면 그 서버의 GPU가 상태와 함께 나옵니다(비어 있음 · 사용 중: 사람 · 다른 학습 중). 쓸 GPU를 눌러 고릅니다.
   - "자동"은 빈 GPU 1개, "CPU만"은 GPU 없이.
   - **사람 전용**으로 빼 둔 GPU(노드 설정)는 고를 수 없습니다.
   - 쓰이고 있는 GPU를 고르면 그 GPU가 빌 때 시작합니다.
   - 이미지가 있는 서버를 여럿 고르면 개수만 고릅니다.
6. **세부 설정**(접힘): 하이퍼파라미터(epoch 등), 환경(자동 설치 · Docker · 등록한 환경), 학습할 클래스(처음엔 모두 골라져 있음. 뺄 것을 눌러 끔), 시작 가중치(등록된 모델에서 이어서), 실행 · 모델 이름.
7. 고르는 동안 Hub가 맞는지 확인합니다. 막는 문제는 빨갛게 보이고 시작 버튼이 꺼집니다(예: 클래스 수, 라벨 있는 이미지 수, 학습용 서버가 아님).
8. **학습 시작**을 누릅니다. 어느 서버든 처음 학습할 때는 환경을 준비하느라 몇 분 더 걸립니다.

> [!NOTE]
> 아직 라벨 안 한 이미지는 학습에서 뺍니다. 이미지가 여러 서버에 흩어진 버전은 아직 학습할 수 없습니다.

#### 실행 이름

- 비워 두면 `데이터셋-버전-모델-오늘 날짜`입니다(예: `COCO8-검출-v1-yolo11n-20261123`, 같은 날 둘째부터 `-2`).
- **다시 실행** · **이어서 실행**은 원래 이름에 오늘 날짜를 붙입니다.
- 실행 이름은 프로젝트가 달라도 Hub 전체에서 하나씩이라, 이미 있는 이름이면 번호가 붙습니다.
- 실행 화면 제목 옆 연필(**이름 바꾸기**)로 바꿉니다. 다른 실행(어느 프로젝트든)이 쓰는 이름으로는 바꿀 수 없습니다.

#### GPU 배정

GPU는 다음을 모두 만족하는 것을 씁니다.

- MOA 작업이 쓰지 않음
- 사람이 쓰는 중으로 보이지 않음(설정의 [GPU 배정 기준](#14-설정-관리자))
- 사람 전용으로 잡히지 않음

빈 GPU가 없으면 이유와 함께 기다립니다.

### 9.4 실행 화면

- **단계**: 대기(또는 이미지 받기) → 데이터 준비 → 환경 준비 → 학습(epoch) → 모델 등록.
- **지표**: 지표 타일과 그래프(정확도 · loss · mAP …), **단계별 지표 CSV로 받기**.
- **그림 · 표**: 학습 코드가 남긴 것(단계를 넘기며 보기, 표에서 찾기 · 정렬).
- **그 밖의 칸**: 학습 데이터 · 설정 · 산출물(전체 내려받기) · 계보 · 클래스별 지표 · 설치된 패키지 · 서버 자원(CPU · 메모리 · GPU) · 로그. 클래스별 표는 열 제목을 누를 때마다 내림차순 → 올림차순 → 기본순으로 정렬합니다.
- **메모 · 태그**: 무엇을 해 봤는지 적어 두면 표에서 찾을 수 있습니다.

| 버튼 | 하는 일 |
|---|---|
| **중단** | 기다리거나 도는 학습을 멈춥니다 |
| **이어서 실행** | 실패하거나 멈춘 학습을 마지막으로 끝난 epoch부터 잇습니다 |
| **다시 실행** | 같은 버전과 설정으로 새 실행을 시작합니다 |
| **삭제** | 휴지통으로. 등록된 모델은 남습니다 |

학습이 끝나면 가중치가 **모델로 자동 등록**됩니다.

### 9.5 하이퍼파라미터 탐색

새 학습 창의 **여러 설정 시험해 보기**에서 시험할 설정과 값(예: `0.01, 0.001` 또는 범위 `0.0001~0.01`)을 적습니다.

| 고를 것 | 내용 |
|---|---|
| 방식 | **모든 조합** · **무작위로 뽑기** · **베이지안**(앞선 결과를 보고 다음을 고름) |
| 실행 수 | 최대 100 |
| 동시에 돌릴 수 | 최대 8 |
| 가장 좋은 것의 기준 | 지표 |

탐색 화면에서 설정값마다 결과 점 그래프와 가장 좋은 설정을 보고, **탐색 멈추기**로 멈춥니다.

## 10. 모델

학습이 끝나면 가중치가 모델 버전으로 등록됩니다. 여기서 평가 · 내보내기 · 테스트하고 별칭을 붙여 관리합니다.

### 10.1 첫 화면과 모델 목록

- **첫 화면**: 모델 버전 수 · 별칭 붙은 버전 · production · 모델 있는 프로젝트, 프로젝트 카드(별칭 붙은 모델과 지표, 최고 지표, 최근 등록).
- **모델 목록**(프로젝트를 누름): 모델 이름 · 버전, 주요 지표, 크기, 학습 데이터, 등록 때.
- 두 버전을 체크하면 지표를 나란히 비교하고, 같은 데이터로 평가한 결과와 클래스별 차이도 보여 줍니다.

### 10.2 모델 화면

- **가중치 받기**, 설명 · 태그.
- **별칭**: champion · production · staging · challenger 같은 이름을 붙입니다(아무 이름이나 가능). 한 모델 이름에서 한 별칭은 한 버전에만 붙고, 다른 버전에 붙이면 옮겨 갑니다.
- **이름 바꾸기**: 제목 옆 연필로 모델 이름(그 이름의 모든 버전)과 이 버전의 번호를 바꿉니다. 같은 이름 · 번호가 있으면 안 됩니다. 계보와 다른 화면, 이름을 적어 둔 기록(이어 학습 · 오토라벨 · 검수 기록)도 함께 바뀝니다.
- **계보**: 버전 → 학습 실행 → 모델 → 평가 · 내보내기 · 테스트가 그림으로 이어집니다.

### 10.3 평가 · 내보내기 · 테스트

**이 모델로 할 수 있는 것**의 버튼은 모델 종류에 그 코드가 있을 때만 켜집니다.

| 버튼 | 하는 일 | 기본 서버 |
|---|---|---|
| **평가** | 버전과 split(val · test · train)을 골라 잽니다. 결과는 검수의 "모델 기준"과 버전 화면의 "라벨 의심 순"에 쓰입니다 | 이미지가 있는 서버 |
| **내보내기** | ONNX · TorchScript | 그 모델을 학습한 서버 |
| **테스트** | 이미지(최대 20장)를 올려 예측을 봅니다 | 그 모델을 학습한 서버 |

- 세 창 모두 **실행할 서버**를 고릅니다. 이미지가 없는 서버에서 평가하면 그 버전의 이미지를 먼저 받습니다. 쓸 수 없는 서버는 이유가 함께 나옵니다.
- 평가는 다른 프로젝트의 버전으로도 합니다(같은 태스크, 모델의 클래스가 그 버전에 있을 때).
- 평가는 지표 · 클래스별 결과 · 이미지별 결과 · 예측을 남기고, 그림은 남기지 않습니다. 이미지마다 틀린 것은 검수에서 데이터셋 이미지 위에 봅니다(평가 화면의 **검수에서 이미지로 보기**).
- 평가 기록은 실행한 사람이나 관리자가 **삭제**합니다(지표 · 파일 · 이미지별 예측이 함께 지워짐).
- 모델 작업(평가 · 검수의 모델 검사 · 오토라벨 · 내보내기 · 테스트)은 학습처럼 가상환경에서 먼저 돕니다(모델 종류가 설치할 패키지를 적었을 때). Docker 이미지로만 학습한 모델도, 그 가중치를 읽는다고 적은 새 버전의 모델 종류가 있으면 그 코드로 가상환경에서 돌고 기록에 "… 코드로"가 붙습니다.

### 10.4 평가 화면

평가 기록의 버전 · split을 누르면 열립니다. 데이터셋 버전 화면의 모델 탭에서도 엽니다.

- 상태 · 서버 · 걸린 시간, 지표(split별 · 클래스별), 결과 파일, 로그.
- **중단** · **다시 실행**(같은 설정, 서버는 고를 수 있음).
- **split별 표**: 행을 손잡이로 끌어 순서를 바꿉니다. 맨 위 split의 지표가 위 카드에 보입니다(val을 위로 올리면 val 기준). 순서는 사람마다 저장되어 모든 평가에 같게 보이고, "원래 순서로"로 되돌립니다.
- **클래스별 표**: 열 제목을 누를 때마다 내림차순 → 올림차순 → 기본순.
- **같은 데이터로 평가한 모델**: 같은 버전 · split으로 평가한 모델을 나란히 비교하고, 셋까지 골라 클래스별로 봅니다.

### 10.5 모델 비교 화면

모델 목록에서 체크한 뒤 "비교 화면에서 보기"(모델 화면에서는 "다른 모델과 비교")로 엽니다. 다른 프로젝트의 모델까지 6개를 나란히 봅니다.

- 같은 버전 · split으로 평가한 결과가 공정한 비교입니다. 없으면 **같은 버전으로 모두 평가**로 한 번에 평가합니다.
- 학습 때 검증 지표와 클래스별 지표도 나란히 봅니다.

## 11. 노드(서버)

학습 · 데이터 서버를 붙이고, GPU와 디스크를 지켜봅니다.

### 11.1 노드 화면

연결된 서버의 GPU를 한 판에 보여 줍니다(5초마다 새로 고침).

**위쪽 숫자**: 빈 GPU · MOA가 쓰는 GPU · 사람이 쓰는 GPU · 사람 전용 · 연결 끊김 · 기다리는 작업.

**서버마다**

- 이름, GPU 이름과 수
- **역할**: 학습용 · 오토라벨용 · 추론용 · 데이터 서버용(역할마다 다른 색)
- CPU · 메모리 · 디스크 막대
- **디스크 공간 부족**: MOA가 쓰는 디스크(노드 홈 · 작업 폴더 · 받은 이미지 · Docker 이미지)가 10 GB 아래이거나 디스크의 5%(최대 50 GB) 아래면 노란 글씨, 3 GB 아래면 빨간 글씨. 글씨에 마우스를 올리면 디스크마다 무엇이 있는지 나옵니다.
- **상태**: 응답 없음, 작업 받지 않음, 버전 차이(작업이 없을 때 스스로 업데이트)

**GPU 칸**: 쓰는 작업(학습 이름 · epoch · 남은 시간) 또는 쓰는 사람, 비어 있음, 사람 전용. 칸이 차오른 높이가 GPU 메모리이고, 온도가 늘 보입니다(75°C부터 주황, 83°C부터 빨강).

### 11.2 서버 추가 (관리자)

1. **노드 추가**를 누르고 역할을 고릅니다.

   | 역할 | 뜻 |
   |---|---|
   | 학습용 | 학습이 돕니다. 모델 종류의 환경이 이 서버에 설치됩니다 |
   | 오토라벨용 | 이미지가 있는 이 서버에서 오토라벨이 돕니다 |
   | 추론용 · 데이터 서버용 | 아직 이 역할로 보내는 작업은 없습니다 |

2. **설치 명령 만들기**를 누릅니다. 한 번만 쓰는, 1시간 동안 유효한 명령이 나옵니다.

   | 서버 | 명령 |
   |---|---|
   | Ubuntu / Linux | `curl … \| sudo bash`. 서비스로 등록되어 재부팅해도 다시 연결됩니다 |
   | Ubuntu / Linux (sudo 권한 없음) | `sudo` 없는 명령. 그 계정의 홈(`~/.badamoa`)에 설치되고 그 계정의 crontab으로 켜집니다 |
   | Windows | 관리자 권한 PowerShell에서 실행 |

3. 서버에서 명령을 실행하면 노드 목록에 나타납니다.

> [!IMPORTANT]
> **Hub 주소**: 명령에 들어가는 Hub 주소가 다른 서버에서 닿는 주소인지 확인하세요. 노드 추가 창의 **바꾸기**에서 고칠 수 있습니다(localhost는 다른 서버에서 이 Hub가 아닙니다).

#### sudo 없이 설치한 노드

- 방화벽은 손대지 않으므로 이미지 전송 포트(8475/tcp)를 관리자에게 열어 달라고 하세요.
- 노드 탭에 "sudo 없이 설치 · 계정 이름"으로 나옵니다.
- 사내 Docker 레지스트리가 HTTPS 없이 열려 있으면 관리자가 한 번 `curl -fsSL <hub>/install/docker-registries.sh | sudo bash`를 실행해야 그 레지스트리의 이미지로 학습합니다.
- 나중에 sudo로 바꾸려면 그 서버에서 sudo 명령을 다시 실행합니다. 같은 노드로 이어받고(등록 · 데이터셋 · 기록 그대로) 그 계정의 노드는 멈춥니다. 학습이 도는 동안에는 이어받지 않습니다.

#### sudo로 설치한 노드

HTTPS 없는 사내 Docker 레지스트리를 스스로 허용합니다(설치 · 업데이트 때와 받다 막혔을 때). Hub의 레지스트리(설정 → 환경)는 처음부터 그 목록에 들어갑니다.

### 11.3 서버 설정 (관리자)

서버 줄의 **설정**에서 바꿉니다.

| 항목 | 내용 |
|---|---|
| 이름 · 역할 | 서버 이름과 맡을 역할 |
| 비활성화 | 새 작업을 보내지 않습니다 |
| **사람 전용 GPU** | MOA가 작업을 보내지 않는 GPU |
| **받은 이미지 보관 위치** | 다른 서버에서 받은 이미지를 둘 곳(자동 = 남은 공간이 가장 많은 디스크) |
| **작업 폴더 위치** | 가상환경 · 학습이 쓰는 폴더 · 받아 둔 모델 가중치 · 모델 종류 코드와 캐시를 둘 곳(아래) |
| **노드 삭제** | 그 서버에서도 MOA를 지울지 고를 수 있습니다. 그 서버의 이미지로 등록한 데이터셋은 더 학습하거나 내려받을 수 없게 됩니다 |

#### 작업 폴더 위치

- **자동**은 남은 공간이 가장 많은 디스크입니다. 처음 한 번 고르고 기억합니다.
- 노드 홈과 같은 디스크면 노드 폴더 그대로이고, 다른 디스크면 그 디스크의 `badamoa-work` 폴더입니다. uv 캐시도 그 디스크(`badamoa-work/uv-cache`)에 둡니다.
- **바꾸면** 그동안의 작업 폴더 · 가중치 · 코드 · 캐시는 작업이 없을 때 한 번 새 자리로 옮깁니다(옮기는 동안 새 작업은 기다림).
- 이미 만든 가상환경은 옮기지 않고 있던 곳에서 계속 쓰며, 새로 만드는 것만 새 자리에 생깁니다. 예전 자리의 가상환경은 노드 상세 → 저장 공간에서 지우면 다음 학습 때 새 자리에 다시 만들어집니다.
- 노드의 설정 · 로그 · 등록 정보는 노드 폴더(Linux sudo 설치 `/var/lib/badamoa/node`, sudo 없이 `~/.local/share/badamoa/node`)에 그대로 있습니다.
- 고른 폴더를 만들거나 쓸 수 없으면(권한 · 없는 디스크) 그 이유가 설정 창에 나오고, 그동안은 노드가 고른 곳을 씁니다.

### 11.4 노드 상세

서버 이름을 누르면 열립니다.

| 칸 | 내용 |
|---|---|
| 지금 상태 | CPU · RAM · GPU 메모리 · 전력 · 업타임, 곧 가득 찰 디스크 경고 |
| **디스크 공간 부족** | 맨 위에 그 디스크 · 남은 공간 · 그 디스크에 있는 것과 비우는 방법([11.5](#115-디스크-공간과-docker-이미지-위치)) |
| **GPU 타임라인** | 누가 언제 어느 GPU를 썼는지(6시간 · 24시간 · 7일). 띠를 누르면 그 실행으로 갑니다 |
| 자세한 그래프와 표 | 1시간~30일: 사용자별 사용량, 디스크, 물리 디스크, 디스크 I/O 사용률 등 |
| **저장 공간** | MOA가 이 서버에 둔 것([11.6](#116-저장-공간)) |
| **받아 둔 버전** | 학습하려고 다른 서버에서 받아 둔 데이터셋 버전. 지우거나 맞춰 볼 수 있습니다 |

데이터셋 버전 화면의 **이 버전이 있는 서버**에서는 등록한 원본 폴더와, 학습하려고 다른 서버가 받아 둔 사본의 폴더를 봅니다.

### 11.5 디스크 공간과 Docker 이미지 위치

MOA가 쓰는 디스크가 부족하면 노드 상세 맨 위에 그 디스크와 그 디스크에 있는 것(노드 홈 · 작업 폴더 · 받은 이미지 · Docker 이미지), 비우는 방법이 나옵니다.

Docker 이미지는 Docker 디스크에 이미지 크기의 3배 이상이 남아 있을 때만 받습니다. 모자라면 노드가 Docker 이미지 위치를 남은 공간이 가장 많은 디스크로 먼저 옮기고 받습니다(sudo로 설치한 Linux 노드이고, 그 서버에 다른 MOA 작업도 돌고 있는 컨테이너도 없을 때). 옮기지 못하면 받지 않고 이유와 비우는 법을 남기고 멈춥니다.

#### Docker 이미지 위치 옮기기 (관리자)

Docker 이미지가 있는 디스크가 부족하면 **Docker 이미지 위치 옮기기**가 나옵니다(저장 공간의 Docker 이미지 줄에도 "다른 디스크로 옮기기").

1. 옮길 폴더를 다른 디스크 목록(남은 공간 · 크기)에서 고르거나 직접 적습니다.
2. 노드가 Docker를 멈추고 → 다른 디스크로 복사하고 → `data-root`를 바꾸고 → 다시 켭니다.
3. 새 위치에서 이미지가 모두 보이면 예전 폴더를 지웁니다. 잘못되면 원래대로 되돌립니다.

> [!WARNING]
> 그동안 그 서버의 컨테이너가 모두 멈춥니다. 돌고 있는 컨테이너가 있으면 확인을 한 번 더 받습니다. sudo로 설치한 Linux 노드에서만 됩니다.

#### 직접 옮기기

같은 칸의 "Docker 이미지 폴더를 여유 있는 디스크로 옮기는 법"을 펼치면, 그 서버에서 직접 실행할 명령이 나옵니다.

1. `sudo systemctl stop docker docker.socket` — 그 서버의 컨테이너가 모두 멈추니 학습이 없을 때
2. `sudo rsync -aHAX /var/lib/docker/ /home4/docker/` — 여유 있는 디스크로 복사
3. `/etc/docker/daemon.json`에 `"data-root": "/home4/docker"`를 넣음(사내 레지스트리 허용 같은 다른 설정은 그대로. 화면의 명령은 기존 내용에 합쳐 씀)
4. `sudo systemctl start docker`, `docker info --format '{{.DockerRootDir}}'`로 새 자리를 확인합니다. 학습이 잘 되면 예전 `/var/lib/docker`를 지워 공간을 비웁니다.

- rootless Docker(`~/.local/share/docker`)는 `systemctl --user`와 `~/.config/docker/daemon.json`으로 같은 순서입니다.
- Windows의 Docker Desktop은 Docker Desktop 설정 → Resources → Advanced → Disk image location에서 옮깁니다.

### 11.6 저장 공간

MOA가 이 서버에 둔 것 — 받은 이미지 · 가상환경 · Docker 이미지 · 모델 가중치 · 모델 종류 코드 · 작업 폴더 · uv 캐시의 크기와 목록입니다.

- **비우기**(관리자): 그 종류의 목록이 창으로 떠서 지울 것을 골라 지웁니다. 처음엔 작업이 쓰지 않는 것이 모두 골라져 있습니다.
- **N개 보기**: 줄 이름 옆을 눌러 펼치면 하나씩 지울 수도 있습니다. 작업이 쓰는 것은 지워지지 않습니다.
- **놓인 곳**: 종류마다 놓인 폴더와 그 디스크 · 남은 공간 · 누가 정했는지가 나옵니다(받은 이미지와 작업 폴더: 노드가 고른 곳 또는 관리자가 정한 곳, Docker 이미지: Docker의 data-root).
- 목록을 펼치면 가상환경 · 작업 폴더 하나하나의 경로가 나옵니다. 아직 예전 자리(노드 폴더)에 있는 것은 "예전 위치"와 그 경로로 나옵니다.

## 12. 작업

MOA가 서버에 보낸 모든 일(가져오기 · 학습 · 평가 · 전송 · 정리 …)의 목록입니다.

- **상태**: 대기 · 실행 중 · 성공 · 실패 · 취소됨. 기다리는 작업은 이유가 보입니다(빈 GPU 부족, 온라인 노드 없음, 그 역할의 서버 없음 등).
- **줄을 누르면** 로그(실시간)와 결과가 보입니다.
- **작업 취소**: 기다리는 작업은 바로 빠지고, 도는 작업은 서버에서 멈춥니다.
- 응답이 없는 서버의 작업은 90초 뒤 "노드 연결이 끊겨 작업을 잃었습니다"로 실패합니다.

## 13. 에이전트 연결 (MCP)

Claude Code 같은 AI 에이전트를 연결하면 MOA의 많은 일을 대화로 시킬 수 있습니다. 에이전트가 할 수 있는 일은 MOA Hub가 내주는 도구(49개)로 정해져 있고, 화면에서 한 것과 똑같이 실제로 일어납니다(작업이 큐에 들어가 GPU를 쓰고, 고친 라벨이 작업 중에 남습니다).

### 13.1 연결하기

1. **에이전트** 화면 → **토큰 만들기** → 이름을 적고 **토큰 발급**. 토큰은 지금 한 번만 보이니 복사해 두세요.
2. **에이전트에 연결하기**의 명령을 복사해 실행합니다. Claude Code는:
   ```bash
   claude mcp add --transport http badamoa http://<Hub 주소>/mcp --header "Authorization: Bearer <토큰>"
   ```
   다른 MCP 클라이언트는 JSON 설정을 씁니다.
3. 에이전트는 토큰을 만든 사람의 권한으로 일합니다. 필요 없어진 토큰은 **폐기**합니다.

같은 토큰을 Prometheus 수집과 `badamoa template push`에도 씁니다.

### 13.2 시킬 수 있는 일

#### 노드 · 작업

- 노드 상태 · 하드웨어 · 자원 이력(디스크가 언제 찰지까지)
- GPU 자리표(지금 어디서 돌릴 수 있는지)
- 작업 목록 · 로그 · 취소, 작업 실행
- 노드 추가 명령 만들기(관리자)

예: "노드 상태 점검해줘", "어제 실패한 작업 원인 봐줘", "지금 학습 돌릴 빈 GPU 있어?"

#### 데이터셋

- 프로젝트 · 데이터셋 · 버전 조회(id 대신 지문 앞부분이나 `데이터셋@버전`도 됨)
- 노드의 폴더를 새 버전으로 **등록**
- 버전 비교, 기존 버전들로 새 버전 만들기(합치기 · 필터)
- 이미지와 라벨 보기, 서버에 받아 둔 사본 확인 · 지우기

예: "AI-201의 /data/street 폴더를 주차장 프로젝트에 street v2로 등록해줘", "street v1과 v2에서 뭐가 바뀌었어?"

#### 라벨 고치기

- 이미지 하나의 라벨 보기 · 고치기(데이터셋의 작업 중에 저장)
- 작업 중을 새 버전으로 확정

예: "이 이미지들의 car 박스를 truck으로 바꿔줘", "고친 것 v3로 확정해줘"

#### 검수

- 규칙 검사 결과(미라벨 · 오라벨 · 박스 오류)와 걸린 이미지
- 이미 평가한 모델 기준으로 걸린 이미지와 그 모델의 예측
- "문제 없음"으로 두기, 버전의 검수 기록

예: "street v3에서 같은 물체에 박스가 둘인 이미지 찾아서 하나 지워줘", "모델이 못 찾은 라벨 많은 순으로 보여줘"

#### 라벨링 · 오토라벨

- 라벨링 묶음 조회 · 만들기(라벨 안 한 이미지, 검수에 걸린 이미지 등 필터로)
- 등록한 모델로 오토라벨

예: "라벨 안 한 이미지로 100장씩 묶음 만들고 champion 모델로 오토라벨 해줘"

#### 학습

- 모델 종류와 설정 칸 보기
- 학습 시작(서버와 GPU 수 고르기, 받아 온 이미지를 끝난 뒤 남기기/지우기)
- 하이퍼파라미터 탐색 시작 · 조회 · 중단
- 실행 조회(진행 중이면 그때까지의 학습 곡선), 메모 · 태그
- 모델 종류의 환경 미리 설치(관리자)

예: "street v3로 yolo11s 100 epoch 학습해줘", "lr0를 0.01과 0.001로 탐색해줘", "지금 도는 학습 mAP 어떻게 돼?"

#### 모델

- 모델 목록 · 조회 · 계보, 설명 · 태그, 별칭(alias) 붙이기

예: "mAP가 가장 높은 모델에 champion 붙여줘", "이 모델은 어떤 데이터로 학습했어?"

#### 준비된 요청

Claude Code에서는 도구 말고도 두 가지 준비된 요청을 바로 쓸 수 있습니다.

- **실패한 작업 진단**: 작업 id를 주면 상태 · 로그로 원인과 다음 할 일을 정리합니다.
- **노드 상태 점검**: 오프라인 노드, 디스크가 모자란 노드, 쉬는 GPU를 한 번에 봅니다.

### 13.3 아직 화면에서만 되는 일

- 모델 **평가 · 내보내기 · 테스트**, 그리고 이것으로 하는 검수의 "모델로 검사하기"와 모델 비교 화면(이미 끝난 평가의 결과는 에이전트도 봅니다)
- 이름 바꾸기와 지우기(데이터셋 · 버전 · 모델 · 평가), 휴지통
- 관리자 설정: 모델 종류 올리기 · 시험 실행 · 허용, 사용자 · 접속 중인 사람, 환경 · Docker 레지스트리 · 사내 패키지, Docker 이미지 위치 옮기기, Hub 옮기기, 보관 기간

### 13.4 알아 둘 것

- **권한**: 토큰을 만든 사람의 역할대로입니다. 멤버의 토큰이면 관리자만 하는 일(노드 추가 명령, 환경 미리 설치 등)은 거절됩니다.
- **실제로 일어남**: 에이전트가 시작한 학습 · 오토라벨 · 등록은 화면에서 시작한 것과 같이 작업 화면에 나오고 GPU를 씁니다. 라벨 고치기는 작업 중에만 남고, 확정하기 전까지 버전은 그대로입니다.
- **오래 걸리는 일**: 등록 · 학습은 작업으로 돌고, 에이전트는 몇 분씩 기다리며 상태를 다시 확인합니다. 그동안 화면에서 같은 작업을 봐도 됩니다.

> [!TIP]
> 큰 일을 시킬 때는 무엇을 할지 먼저 말해 달라고 하면 안전합니다.

> [!WARNING]
> 토큰이 새어 나갔거나 더 쓰지 않으면 **에이전트** 화면에서 바로 폐기하세요. 폐기하면 그 토큰으로 연결한 에이전트는 즉시 멈춥니다.

## 14. 설정 (관리자)

멤버도 설정을 볼 수는 있지만, 바꾸는 것은 관리자가 합니다. 관리자가 "모델 종류 올리기"를 켜 준 멤버는 설정 → 모델 종류의 **내 PC에서 만들어 올리기**에서 도구 설치 · 시험 실행 · 올리기 명령과 토큰을 받습니다.

| 탭 | 내용 |
|---|---|
| **모델 종류** | 학습에 쓰는 모델 종류(템플릿)와 버전, 올리고 허용하기([14.1](#141-모델-종류)) |
| **환경** | 학습 환경, 사내 패키지, Docker 레지스트리([14.2](#142-환경)) |
| **프로젝트 기본값** | 프로젝트마다 기본 모델 종류 |
| **GPU 배정** | GPU를 "사람이 쓰는 중"으로 보는 기준(메모리 사용 % · 사용률 %). "보지 않음"은 MOA만 쓰는 서버용 |
| **Hub 저장 공간** | Hub에 보관한 것의 크기와 정리([14.3](#143-hub-저장-공간)) |
| **사용자** | 계정과 역할([14.4](#144-사용자)) |
| **Hub 실행** | 재부팅 시 자동 실행([14.5](#145-hub-실행)) |
| **Hub 옮기기** | Hub를 다른 PC로([14.6](#146-hub-옮기기)) |
| **내 계정** | 비밀번호 바꾸기(다른 곳의 로그인은 끝남) |
| **외부 모니터링** | Prometheus로 Hub와 서버 지표를 수집하는 설정 |

### 14.1 모델 종류

학습에 쓰는 모델 종류(템플릿) 목록과 버전, 할 수 있는 것(학습 · 평가 · 추론 · 내보내기), 기본 환경이 나옵니다. 만들고 올리는 방법은 [템플릿 가이드](TEMPLATE_GUIDE.md)에 있습니다.

- **버전 칸**: 기본 제공은 실제 라이브러리 버전(예: ultralytics 8.4.216)으로 보이고, 템플릿 번호는 그 아래 작게 나옵니다. 서버에서 돈 학습이 설치한 버전이고(서버마다 다르면 가장 새 것, 마우스를 올리면 서버별), 아직 설치 전이면 지금 설치하면 받을 버전입니다. 올린 모델 종류는 자기 버전 아래에 라이브러리 버전이 나옵니다.
- **이름**을 누르면 그 모델 종류의 설명을 보고 고칩니다(비우면 올린 파일의 설명).
- **버전**을 누르면 버전마다 올린 사람 · 때 · 시험 상태 · 메모를 보고 메모를 고칩니다.
- **이 버전의 코드 받기**(관리자): 코드와 설치에 필요한 것(`requirements.txt` · `requirements.lock.txt` · `wheels/`)을 받습니다.
- **환경 관리**: 어느 서버에 환경을 미리 설치할지 고르고, 설치한 환경을 지웁니다.

#### 올린 버전을 쓰게 하기

1. 올린 버전은 **시험 전**입니다. 다른 사람에게 보이지 않습니다.
2. 관리자가 **시험 실행**을 누릅니다(학습용 서버 한 대, 빈 GPU가 있으면 GPU).
3. 통과하면 **통과 · 허용 대기**가 됩니다.
4. **허용**하면 모두에게 보입니다.

- 실패하면 단계 · 이유 · 로그를 보고 다시 시험합니다.
- 급할 때는 이유를 적고 "통과 없이 허용"합니다.
- 멤버가 올린 것은 **초안**(올린 사람만 봄)이고, 그 옆에 "올린 사람 PC에서 통과" 보고서가 보입니다.

### 14.2 환경

- **학습 환경**: 자동 설치(기본), 서버에 있는 Python, Docker 이미지. 추가 · 연결 확인 · 수정 · 지우기.
- **사내 패키지**: PyPI에 없는 wheel(.whl)을 올리면 서버가 환경을 만들 때 Hub에서 받아 설치합니다.
- **Docker 레지스트리**: Hub가 스스로 마련한 레지스트리(이 PC에 있던 것을 쓰거나, 없으면 Hub 폴더에 만듦)의 주소 · 연결 · 보관 폴더가 나옵니다.
  - 모델 종류 · 환경이 쓰는 이미지가 그 안에 있는지 확인합니다.
  - 없으면 **레지스트리에 올리기**(Hub PC에 이미지가 있을 때) 또는 이미지를 만든 PC에서 할 `docker push` 명령이 나옵니다.
  - 다른 레지스트리 주소를 적거나 끌 수 있습니다.

### 14.3 Hub 저장 공간

- Hub에 보관한 것(모델 · 산출물 · 체크포인트 · 휴지통 · 데이터셋 썸네일 · 기록(DB))의 크기와 프로젝트별 사용량(이미지 수 · 데이터셋 용량).
- 보관 기간과 정리.
- **DB 압축**: 지운 기록이 남긴 DB 안의 빈 공간을 디스크에 돌려줍니다. 휴지통을 비운 뒤 빈 공간이 크면 Hub가 쉴 때 알아서 합니다.

### 14.4 사용자

| 하는 일 | 내용 |
|---|---|
| 사용자 추가 | 첫 비밀번호를 정합니다 |
| 역할 | 멤버 · 관리자 |
| **모델 종류 올리기** | 멤버가 모델 종류를 초안으로 올릴 수 있게 켭니다 |
| 비밀번호 재설정 | 잊은 사람의 비밀번호를 새로 정합니다 |
| 중지 · 다시 사용 | 잠시 막기만 할 때 |
| **삭제** | 계정을 지웁니다. 바로 로그아웃되고 API 토큰도 지워지며, 같은 아이디로 새 계정을 만들 수 있게 됩니다 |

- 지운 사람이 만든 데이터셋 · 라벨 · 학습 · 모델은 그대로 남습니다(만든 사람만 비어 보임). 라벨링 묶음에서 맡은 일감은 담당자가 비워져 다른 사람이 맡을 수 있습니다.
- 자기 계정과 마지막 관리자는 지울 수 없습니다.
- "마지막 사용"에 지금 접속 중인지와 IP가 나옵니다.

### 14.5 Hub 실행

"재부팅 시 자동 실행"을 켜고 끕니다. 지금 Hub가 도는 그대로(데이터 폴더 · 포트 · 주소 등) 실행되게 등록하고, 노드는 Hub가 켜지면 알아서 다시 붙습니다. 콘솔 창 없이 돌고 출력은 데이터 폴더의 `hub.log`에 남습니다.

| Hub PC | 켜지는 때 |
|---|---|
| Windows, 관리자 권한으로 띄운 Hub | 로그인 없이 부팅 때 |
| Windows, 그 밖 | 그 계정이 로그인할 때. 화면에 나오는 명령을 관리자 PowerShell에서 한 번 실행하면 부팅 때로 바뀝니다 |
| Ubuntu, root | systemd로 부팅 때 |
| Ubuntu, 그 밖 | 그 계정의 crontab으로 부팅 때 |

### 14.6 Hub 옮기기

Hub를 다른 PC로 옮길 때 파일 하나(`badamoa-hub-<날짜>.tar`)로 내보내고 새 PC에서 가져옵니다.

1. 내보낼 폴더를 이 PC의 디스크 목록에서 고르거나 직접 적고 내보냅니다. 돌고 있는 작업이 있으면 끝난 뒤에 합니다. 다 되면 새 PC의 브라우저에서 받을 수 있는 내려받기 링크가 나옵니다.
2. 내보내기를 누른 때부터 이 Hub는 **읽기만** 됩니다(로그인 · 보기는 됨). "옮기기 취소"로 다시 씁니다.
3. 새 PC에서 Hub를 켜기 전에 `uv run badamoa hub import <파일> --home <Hub 폴더>`를 실행합니다.
4. 새 Hub를 켠 뒤 예전 Hub의 같은 화면에 새 Hub 주소를 적습니다. 노드는 새 Hub로 넘어가고, 예전 주소로 접속한 사람은 새 Hub로 안내됩니다. 화면에 노드마다 아직 예전 Hub에 붙어 있는지 나옵니다.

> [!NOTE]
> 파일에는 DB · 썸네일 · 결과 파일 · 가중치 · 모델 종류 · 노드 패키지가 들어갑니다. 데이터셋 원본과 받아 둔 이미지는 노드에, Docker 이미지는 레지스트리에 그대로 있습니다. Hub를 끈 채로 내보내려면 `uv run badamoa hub export <폴더> --home <Hub 폴더>`를 씁니다.

## 15. 휴지통

지운 프로젝트 · 데이터셋 버전 · 학습 · 모델 · 모델 종류가 모입니다.

- **되살리기**: 골라서 되살립니다(멤버는 자기가 만든 프로젝트와 학습, 관리자는 모두).
- **완전히 지우기** · **휴지통 비우기**: 관리자만 하고, 되돌릴 수 없습니다. 노드에 등록한 이미지 파일은 언제나 그대로 둡니다.
- 다른 것이 아직 가리키는 버전 · 학습은 계보가 끊기지 않게 남겨 둡니다(이유가 보임).

## 17. 자주 묻는 것

### 학습이 "대기"에서 안 넘어가요

작업 화면이나 학습 표의 상태 칸에 기다리는 이유가 있습니다.

- 빈 GPU가 없으면(다른 학습이나 사람이 쓰는 중) 비는 대로 시작합니다.
- "학습용 역할의 서버가 없다"면 노드 설정에서 역할을 켜세요.

### 처음 학습이 오래 걸려요

그 서버에서 처음 쓰는 모델 종류면 환경(PyTorch 등)을 설치합니다. 다음부터는 바로 시작합니다. 관리자는 설정 → 모델 종류 → 환경 관리에서 미리 설치해 둘 수 있습니다.

### 같은 이름으로 다시 가져오려는데 "이미 있습니다"가 나와요

버전 이름은 데이터셋 안에서 하나입니다. 다른 버전 이름을 쓰거나 이전 버전을 휴지통에서 완전히 지우세요. 실패하거나 중지한 등록은 남기지 않으므로 같은 이름을 다시 쓸 수 있습니다.

### 고친 라벨이 학습에 안 들어가요

고친 라벨은 작업 중에 있습니다. "버전으로 확정"으로 새 버전을 만들고 그 버전으로 학습하세요([5장](#5-작업-중과-버전으로-확정)).

### 서버의 디스크가 모자라다고 나와요

노드 상세 맨 위의 "디스크 공간 부족"에 그 디스크에 무엇이 있고 어떻게 비우는지 나옵니다. 저장 공간에서 쓰지 않는 가상환경 · Docker 이미지 · 받아 둔 버전을 지우거나, 작업 폴더 · Docker 이미지 위치를 여유 있는 디스크로 옮기세요([11.5](#115-디스크-공간과-docker-이미지-위치)).

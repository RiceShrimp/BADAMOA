# 레퍼런스 분석 — Ultralytics Platform · Roboflow

두 플랫폼의 화면 구성과 구성요소를 로그인 상태에서 살펴보고, BADAMOA가 **무엇을 배우고 무엇을 다르게 하는지** 정리한 문서입니다.
(2026-11 기준 관찰. 화면 캡처나 문구는 옮기지 않았고 구조만 기록했습니다.)

원칙: **업계 공통 패턴은 따르고, 이름·분류 체계·모양은 BADAMOA 것으로 만든다.**
같은 문제를 푸는 도구라 "데이터셋 → 학습 → 모델 → 배포" 흐름이 닮는 것은 자연스럽지만,
메뉴 이름과 배치, 색, 문구, 아이콘, 화면 조합을 그대로 가져오면 표절처럼 보입니다.

## 1. 관찰한 구조

### Ultralytics Platform

| 영역 | 구성 |
|---|---|
| 사이드바 | 검색(단축키) · Home / Explore / Agents · **작업 단계별 그룹**: Annotate(데이터셋 목록이 바로 펼쳐짐) · Train(프로젝트 목록) · Deployments · Help / Settings · 계정 |
| 상단 바 | 경로(소유자 › 종류 › 이름 + 공개 여부) · 크레딧 · 언어 · 알림 · 테마 전환 |
| Home | 환영 카드 + **개수 타일**(데이터셋·이미지·어노테이션·프로젝트·모델·export·배포) · 데이터셋/프로젝트 카드(**끌어다 놓기 업로드**) · **저장 공간 카드**(종류별 비율, 큰 항목) |
| 데이터셋 | 머리말(이름 · 태스크 · 라이선스 · 상태) + 요약 줄(이미지 · 라벨됨 · 어노테이션 · 용량 · 수정일) · 탭: **Images / Classes / Charts / Models / Versions** · split 필터(All/Train/Val/Test) · 정렬 · 검색 · 보기 전환 |
| 프로젝트 | 왼쪽에 모델 목록(체크박스, 태스크별 묶음) → 오른쪽에 **선택한 모델 비교 차트** · 가중치 파일 끌어다 놓기 |
| 모델 | 머리말 배지(태스크 · 버전 · 라이선스) · **지표 카드 4개**(mAP50, mAP50-95, Precision, Recall) + 학습 데이터셋 카드 · 탭: **Overview / Train / Predict / Export / Deploy** · 실행 정보(소요 시간, 부모 모델, **재현용 명령**) · 하이퍼파라미터 표(검색·내보내기) · 지표 표 |
| Agents | 블록을 이어 붙이는 워크플로 편집기 |
| Settings | Profile · API Keys · Plans · Billing · Usage · Teams · Integrations · **Trash** |

## 2. 배울 점 → BADAMOA 설계에 반영

| 패턴 | 왜 좋은가 | BADAMOA 반영 |
|---|---|---|
| 작업 단계별 사이드바 | 메뉴가 곧 작업 순서라 처음 써도 길을 안다 | BADA 4단계 + MOA로 묶음 (3장) |
| 워크스페이스 단위 자산 라이브러리 | 이미지가 데이터셋에 갇히지 않아 재사용·검색이 쉽다 | **샘플 라이브러리 → 데이터셋 → 버전** 3층 구조로 명시 |
| 엔티티 머리말 + 요약 줄 + 탭 | 어느 엔티티 화면이든 같은 자리에서 같은 정보를 찾는다 | 데이터셋·모델·노드 상세 화면 공통 틀 |
| 모델 화면의 지표 카드 + 탭 | 핵심 수치가 먼저, 세부는 탭으로 | 모델: 개요 / 학습 / 테스트 / 내보내기 / 배포 / **계보** |
| 재현용 명령과 실행 정보 | 결과를 다시 만들 수 있다는 신뢰 | Run 화면에 "같은 설정으로 다시 실행" + CLI·MCP 호출 예시 |
| 프로젝트에서 모델 여러 개 비교 | 실험의 목적은 비교 | 학습 화면에서 Run 다중 선택 → 곡선·지표 겹쳐 보기 |
| split 필터, 클래스·분포 차트 | 데이터 문제를 학습 전에 본다 | 데이터셋 탭: 샘플 / 클래스 / 분포 / 품질(QA) / 버전 |
| 끌어다 놓기 가져오기 | 첫 사용 장벽이 낮다 | 홈·데이터셋 화면에 드롭 영역 (Phase 1) |
| 에이전트가 첫 화면 | "무엇을 하고 싶은가"에서 출발 | Phase 6 이후 홈 상단에 에이전트 입력창. 지금은 "시작하기" 체크리스트 |
| 코딩 에이전트 연결 | 외부 에이전트를 1급으로 대우 | 이미 구현: 에이전트 화면의 토큰 + 연결 명령 |
| 활동 피드, 감사 로그 | 누가 무엇을 했는지 | 구현: 홈의 "최근 활동" (감사 로그 기반) |
| 휴지통 | 삭제를 되돌릴 수 있다 | 데이터셋·모델은 **soft delete + 휴지통** (Phase 1) |
| 저장 공간 카드 | 무엇이 용량을 쓰는지 | 저장 위치별 사용량·큰 항목 (Phase 2) |
| 모델 모니터링, Vision Events | 배포 뒤가 진짜 시작 | Automate의 피드백·드리프트 화면 (Phase 5) |
| Edge Devices 탭 | 기기가 배포의 단위 | 배포 화면에서 추론 노드(서버·Jetson)별 현재 버전·상태 |
| 전역 검색(단축키) | 화면이 늘어도 한 번에 이동 | 명령 팔레트 (Phase 2) |
| 필터 칩, 개수 타일 | 한눈에 상태 파악 | 구현: 작업 화면 상태 칩, 각 화면 상단 통계 |

## 3. 다르게 하는 점

두 플랫폼은 **클라우드 서비스**이고 BADAMOA는 **사내 설치형**입니다. 여기서 차이가 납니다.

- **MOA(운영)가 1급 메뉴.** 노드·작업·저장 위치·플러그인은 클라우드 서비스에는 없는 화면이고 BADAMOA에서는 핵심입니다. 크레딧·요금제·공개 여부·커뮤니티 탐색은 없습니다.
- **분류 체계는 BADA.** Annotate / Train / Deploy 같은 이름을 가져오지 않고 Build · Annotate · Develop · Automate + MOA로 묶습니다. 학습·평가·레지스트리·export가 "Develop" 하나에 들어가는 것이 다릅니다.
- **계보와 출처가 화면에 보인다.** 라벨이 사람/오토라벨/합성 중 어디서 왔는지, 배포된 모델이 어느 데이터셋 버전에서 나왔는지를 배지와 "계보" 탭으로 보여 줍니다.
- **승인함.** 모델 승격·배포·삭제는 승인 요청으로 쌓이고 사람이 처리합니다(에이전트가 요청해도 동일).
- **모양.** 밝은 테마 기본 + 밝은 사이드바, 청록 포인트, 물결 마크, 한국어 문구. 두 플랫폼의 색·로고·문구·아이콘은 쓰지 않습니다.
- **플러그인 중심.** 특정 모델 계열에 묶이지 않고 Trainer·Labeler를 플러그인으로 고릅니다.

```

          데이터셋         목록 → 상세 탭: 샘플 / 클래스 / 분포 / 품질 / 모델 / 버전

```

## 5. 세부 구성요소 — 프로젝트·데이터셋·버전

두 번째 관찰에서 각 화면 안쪽까지 확인한 내용입니다.

### 5.1 묶는 단위 (폴더 · 프로젝트)

| | Ultralytics | Roboflow |
|---|---|---|
| 최상위 | 계정(워크스페이스) 페이지 — 탭: Datasets / Projects / Deployments | 워크스페이스 — Projects 목록(검색 · 정렬 · 오름/내림) |
| 폴더 | 없음 | **폴더**로 프로젝트를 묶음(New Folder, 프로젝트를 폴더로 이동, 빈 폴더 안내) |
| 프로젝트의 뜻 | **모델을 담는 그릇.** 데이터셋과는 별개 엔티티 | **태스크 하나 = 데이터셋 하나 + 그 모델들.** 프로젝트 안에 데이터가 들어 있음 |
| 프로젝트 내부 | 모델 목록(태스크별 묶음, 체크박스) + 비교 차트(Metrics / Loss / Learning Rate, 차트 설정) + 가중치 업로드 | 2단 사이드바: **DATA**(Upload Data · Annotate · Dataset · Versions · Analytics · Classes & Tags) / **MODELS**(Train · Models · NAS · Test) / **DEPLOY**(Deployments · Active Learning) |

### 5.2 데이터 넣기

- **Roboflow Upload**: 업로드 단위가 **배치**(이름 + 태그). 파일 · 폴더 · 카메라, 이미지 / 어노테이션(여러 포맷) / 영상 / PDF / zip, 휴대폰 QR 업로드, 공개 데이터셋 검색에서 가져오기.
- **Ultralytics**: 데이터셋 화면이나 홈에 바로 끌어다 놓기(이미지 · 영상 · 데이터셋 압축 파일).

### 5.3 데이터셋 화면

| | Ultralytics | Roboflow |
|---|---|---|
| 머리말 | 이름 · 태스크 · 라이선스 · 상태(Ready) · 공개 여부, 요약 줄(이미지 · 라벨됨 · 어노테이션 · 용량 · 수정일), 동작: 새 모델 · 공유 · 다운로드 · 즐겨찾기 | 이름 · "Train Model" 버튼 |
| 탐색 | 검색(이름 · 클래스 · 메타데이터 · **내용 설명**) · 정렬 · 보기 3종(그리드 / 촘촘히 / 표) · 어노테이션 표시 전환 | 검색 · **필터 추가** · 원시 쿼리 · **이미지로 검색** · 정렬 · 어노테이션 표시 · 목록/그리드 · 100개씩 페이지 |
| split | 이미지마다 색 점, 상단 All / Train / Val / Test 필터 + 비율 막대 | 이미지마다 split 배지 |
| 클래스 | 표(index · 이름 · 어노테이션 수 · 이미지 수) · **합치기** · 삭제 | 색 · 이름 · 개수 · 수정 · **클래스 잠금** · 태그 탭 |
| 통계 | Charts: split 분포 · 상위 클래스 · 이미지 크기 분포 · 가로×세로 히트맵 · **박스 중심 위치 분포** | Analytics(데이터셋 건강도) |
| 연결 | Models 탭: 이 데이터셋으로 학습한 모델 | — |

### 5.4 라벨링 흐름 (Roboflow Annotate)

**보드**: 미배정 → 라벨링 중 → (검수 모드를 켜면 검수) → 데이터셋. 배치를 작업자에게 배정하고, Insights 탭에서 진행 상황을 본다.

### 5.5 버전

| | Ultralytics | Roboflow |
|---|---|---|
| 만드는 법 | 설명(선택)만 쓰고 **한 번에 생성** | **5단계**: 원본 이미지 → train/test 분할(비율 · 재분배) → 전처리 → 증강 → 생성 |
| 버전의 내용 | 이미지 · 클래스 · 어노테이션의 **불변 스냅샷**(NDJSON 내보내기) | 그 시점의 스냅샷 + **전처리·증강이 적용된 결과물** |
| 이름 | — | 기본값이 생성 시각, 메모 가능 |
| 눈여겨볼 점 | 데이터셋은 계속 고치고, 버전은 재현용으로만 찍음 | 전처리·증강을 **학습 단계에서 지정**하는 쪽을 권장하는 안내가 있음(버전을 새로 만들지 않아도 됨). 이전 버전의 증강 설정 재사용 |

### 5.6 학습 · 모델 · 내보내기

- **Ultralytics 모델 화면**: Overview(지표 카드 · 실행 정보 · 재현 명령 · 설정 표 · 지표 표) / Train(**Metrics · Console · System** 하위 탭) / Predict(이미지 · 웹캠, confidence · IoU · 이미지 크기, 결과와 **응답 JSON**) / Export(형식 목록 — **형식마다 설정을 달리해 여러 번** 내보내기, 전체 내보내기) / Deploy(리전 선택).
- **Roboflow**: Train(직접 설정 vs 자동 탐색 중 선택) · Models · Test(시각 확인) · Deployments · Active Learning.

## 6. BADAMOA의 결정

| 주제 | 결정 | 근거 |
|---|---|---|
| 묶는 단위 | Hub → **폴더**(선택, 1단) → **프로젝트** → 샘플 라이브러리 · 데이터셋 여러 개 · Run · 모델 | Roboflow의 폴더는 프로젝트가 늘면 필요하다. 프로젝트는 "데이터셋 1개"(Roboflow)도 "모델만"(Ultralytics)도 아닌 **온톨로지를 공유하는 작업 범위**로 둔다 — 학습용 풀과 golden set처럼 데이터셋이 여럿 필요하기 때문 |
| 가져오기 | 모든 가져오기는 **배치**(이름 · 태그 · 출처 · 시각)로 기록 | 가져오기 취소, 배치 단위 오토라벨·검수 배정, "어디서 온 데이터인가" 필터 |
| split | 데이터셋 안에서 샘플의 속성. 비율 지정 + **그룹 단위**(카메라·장면·시간) 재분배. 버전을 찍으면 고정 | 두 플랫폼과 같은 모델에 누수 방지를 더함 |
| 버전 | **한 번에 찍는 순수 스냅샷**(샘플 · 라벨 · split · 온톨로지). 이름 기본값 = 시각, 메모, 통계, **직전 버전과의 차이**(추가/제거 샘플, 바뀐 라벨) | Ultralytics 방식. 차이 보기는 BADAMOA 추가 |
| 전처리 · 증강 | 버전에 굽지 않고 **학습 설정(Run)** 에 둔다 | Roboflow도 이 방향을 권장. 이미지 복제가 없어 저장 공간이 절약되고, 같은 버전으로 설정만 바꿔 실험할 수 있다 |
| 내보내기 | 버전에서 YOLO · COCO · NDJSON 등으로 내보내기(노드 캐시) | 외부 도구·수동 학습과의 호환 |
| 클래스 | 색 · 이름 · 개수 · 합치기 · 삭제 · 잠금 + **클래스별 프롬프트 · 임계값**(오토라벨용) | 앞부분은 공통 패턴, 뒷부분은 BADAMOA 고유 |
| 데이터셋 탭 | 샘플 / 클래스 / 분포 / 품질 / **모델** / 버전 | "이 데이터셋으로 만든 모델" 탭을 추가 |
| 분포 차트 | split · 클래스 · 이미지 크기 · 가로×세로 · 박스 위치 + **출처별**(사람/오토라벨/합성) | 마지막이 BADAMOA 추가 |
| 탐색 | 이름 · 클래스 · 메타 · 태그 필터, 텍스트(의미) 검색, 이미지로 검색, 보기 3종 | 두 플랫폼의 합집합 |
| 라벨링 보드 | 배치 단위 칸반: 미배정 → **오토라벨** → 검수 → 완료 | Roboflow 보드에 오토라벨 칸을 더함 |
| 학습 화면 | Run 상세 하위 탭: 지표 / 콘솔 / **시스템**(노드 GPU·메모리) | 노드 지표는 이미 수집 중 |
| 모델 테스트 | 이미지 · 웹캠 · RTSP, confidence · IoU · 크기 조절, **응답 JSON 보기** | 제품 연동 개발자가 바로 쓰는 정보 |
| 모델 내보내기 | 형식 × 설정(크기 · 정밀도 · 대상 기기)별로 여러 개 보관 | Engine 엔티티와 일치 |

## 7. 확인하지 못한 것

- 어노테이션 에디터 내부(도구 배치, 단축키) — 열면 작업 상태가 바뀔 수 있어 들어가지 않음. Phase 3 착수 때 다시 본다.
- Roboflow Workflows 편집기, Vision Events, Model Monitoring, Active Learning 내부 — 빈 화면이거나 로딩만 확인.
- Ultralytics 배포 화면은 리전 선택 표까지만 확인. 팀·권한 설정은 보지 않음.
- 두 플랫폼 모두 새로 만들기 대화상자는 열지 않았다(생성으로 이어질 수 있어서).

# 라벨링 계획 — 바로 고치기 · 라벨링 · 오토라벨

지금 라벨은 **가져오기로만** 들어온다(YOLO · COCO · 클래스별 폴더). 화면에서 라벨을 고치거나 그리는 기능은 없다.
이 문서는 두 가지를 계획한다.

1. **바로 고치기**: 버전(릴리스)의 이미지를 보다가 틀린 박스 · 틀린 클래스 · 빠진 라벨을 그 자리에서 고쳐 저장하고, 고친 것을 모아 새 버전으로 만든다. 작고 바로 쓸 수 있다 (3장).
2. **라벨링**: 라벨 없는 이미지를 BADAMOA 안에서 라벨링 · 오토라벨 · 검수까지 한다. 프로그램 하나에 가까운 큰 일이라 단계로 나눈다 (4장).

1의 편집 화면과 저장 방식이 2의 바탕이 된다. 그래서 1을 먼저 만든다.

## 1. 원칙

- **라벨은 덮어쓰지 않는다.** 고친 라벨도 새 라벨 개정이다. 버전은 불변이라, 고친 라벨은 **새 버전**으로만 들어간다. 이미 학습에 쓴 버전은 그대로 남는다.
- **Hub는 얇게.** 그리기 · 편집은 브라우저에서, 무거운 모델(SAM · OVD · VLM)은 노드에서 돈다. Hub에는 torch를 넣지 않는다.
- **설치는 가볍게.** Lightly Studio는 기본 설치에 torch · DuckDB · PostgreSQL 드라이버 · pandas · OpenCV가 들어가고, FiftyOne은 MongoDB가 딸려 온다. 이런 무게를 Hub에 들이지 않는다.
- **여러 사람이 쓰는 기능이 기본.** Lightly Studio에서 Enterprise로만 열리는 여러 사용자 · 권한 · 서버 실행을 BADAMOA는 이미 갖고 있다(계정 · Hub · 노드). 배정 · 검수 · 역할도 기본 기능으로 둔다.
- **겉은 단순하게.** 데이터셋 화면에서는 "고치기" 버튼 하나로 시작한다. 라벨링 작업은 왼쪽 메뉴 Annotate에 따로 둔다.

## 3. 1단계 — 바로 고치기

**흐름**: 버전의 이미지를 넘겨 보다가 틀린 것을 발견 → 그 화면에서 고치고 저장 → 고친 이미지가 버전 화면에 모임 → "새 버전 만들기".

### 3.1 화면

- **항목 보기의 "고치기"(단축키 E)**: 같은 화면이 편집 상태로 바뀐다.
  - 박스: 고르기 · 옮기기 · 크기 바꾸기 · 지우기(Delete) · 새로 그리기(B, 드래그) · 복사 · 붙여넣기.
  - 클래스: 고른 박스의 클래스를 오른쪽 목록에서 고르거나 숫자키(1~9)로.
  - 배경으로: 박스를 모두 지우고 "찾을 것이 없는 이미지"로.
  - 되돌리기 · 다시 하기(Ctrl+Z · Ctrl+Shift+Z), 저장(Ctrl+S). 다음 · 이전 이미지로 넘어가면 저장하고 넘어간다. 저장하지 않고 나가려면 Esc.
  - 태스크별 범위: Det는 박스 전부, Cls는 클래스 바꾸기. Seg · Kpt는 이 단계에서 클래스 바꾸기 · 지우기만 하고, 윤곽 · 점 모양 고치기는 4장의 에디터에서 한다.
- **버전 화면의 띠**: "이 버전에서 고친 이미지 12장 · 보기 · 새 버전 만들기 · 모두 되돌리기". "보기"는 그리드를 고친 이미지만으로 거른다. 그리드 썸네일에는 고친 표시를 단다.
- **새 버전 만들기**:
  - 이 버전의 이미지 · split은 그대로 두고, 고친 이미지만 새 라벨을 가리키는 버전을 만든다.
  - 이름 · 메모 기본값을 채운다(예: 메모 "이미지 12장 라벨 수정").
  - 만든 버전의 비교 탭에는 "라벨 변경 12"로 보인다.
  - 지금의 버전 만들기 대화상자에도 "고친 라벨 넣기(12장)"를 둔다. 필터 · split 재분배 · 클래스 바꾸기와 함께 쓸 수 있다.
- **이미 새 버전이 있는 경우**: v1에서 고쳤는데 v2가 이미 있으면, 고친 라벨을 v1에 얹을지 최신 v2에 얹을지 고른다. v2에서 같은 이미지의 라벨이 따로 바뀌었으면 그 이미지는 겹친다고 알려 준다.

### 3.2 저장 방식

- **저장할 때**: 새 라벨 개정을 하나 만든다. 출처는 `human:<사람>`이고, 고친 사람과 바탕이 된 개정을 기록한다. 내용이 기존 개정과 같으면 그 개정을 다시 쓴다.
- **고친 것 목록(`label_edits`)**: (버전, 이미지)마다 새 개정 · 고친 사람 · 시각을 둔다. 버전 자체는 바뀌지 않으므로 학습 · 비교 · 내보내기에는 영향이 없다.
- **두 사람이 같은 이미지를 고치면**: 저장할 때 내가 열었던 라벨과 지금 목록의 라벨이 다르면 "다른 사람이 먼저 고쳤습니다 — 그 라벨 보기 / 내 것으로 저장"을 묻는다.
- **새 버전을 만들면**: 고친 것 목록은 "vX에 들어감"으로 닫힌다. 남겨 둔 것은 다음 새 버전에 들어간다.
- **기록과 권한**: 고친 기록은 감사 기록에 남긴다. 처음에는 로그인한 사람 모두 고칠 수 있다. 라벨러 · 검수자 역할은 4장에서 둔다.
- **MCP 도구**: 라벨 고치기와 새 버전 만들기를 넣어, 에이전트도 같은 길로 라벨을 고친다.

### 3.3 잘못된 라벨 찾기 (바로 고치기 다음)

틀린 라벨을 사람이 넘겨 보며 찾기는 어렵다. Lightly Studio처럼 **모델의 예측과 라벨이 어긋나는 이미지부터** 보여 준다.

- **이미 있는 것**: 평가 작업이 이미지마다 맞춘 것 · 놓친 것 · 더 찾은 것을 기록한다(`templates/yolo/ops.py`의 `per_image`).
- **더할 것**:
  - 평가가 이미지별 예측 박스도 남긴다. 예측은 따로 저장해 버전에 섞이지 않게 한다.
  - 버전 화면 그리드에 "라벨 의심 순" 정렬을 둔다. 고른 모델의 평가에서 놓침과 더 찾음이 많은 이미지가 앞에 온다.
  - 항목 보기에서 예측을 점선으로 겹쳐 본다. 예측 박스를 눌러 "라벨로 넣기"를 하면 빠진 라벨이 바로 채워진다.
- 학습한 모델이 라벨 오류를 찾아 주고, 사람은 고치기만 하는 고리가 생긴다. 고친 뒤 새 버전으로 다시 학습하면 그 효과도 비교 탭에서 바로 확인한다.

## 4. 2단계 이후 — 라벨링 (Phase 3를 "라벨링 · 오토라벨"로 넓힘)

**프로그램을 따로 두지 않고**, 같은 Hub 안에 Annotate라는 자기 영역(왼쪽 메뉴, `hub/annotate/`, `web/src/annotate/`)으로 만든다.
같은 이미지 · 라벨 개정 · 계정 · 노드를 쓰기 때문이다. 따로 두면 둘 사이를 맞추는 일이 생기고, 설치가 둘이 된다.

| 단계 | 내용 | 바탕 |
|---|---|---|
| **3A 라벨링 묶음** | 버전 · 필터 · 태그 · 가져오기 배치에서 이미지를 골라 **라벨링 묶음**을 만든다(클래스 · 태스크 · 지시문). N장씩 나눠 사람에게 배정한다. 보드는 미배정 → 오토라벨 → 라벨링 → 검수 → 완료이고, 완료되면 3장과 같은 길로 새 버전이 된다. **"아직 라벨 안 함" 상태**도 다시 둔다. 0.34.0부터 라벨 없는 이미지는 배경으로 들어오기 때문에, 라벨링할 이미지는 가져올 때 이렇게 표시한다 | CVAT 일감 배정, Roboflow 보드 |
| **3B 에디터** | 도형을 차례로 늘린다: 박스 → 폴리곤 → 점 · 스켈레톤(라벨 공간의 점 이름 · 연결선) → 브러시 마스크 → 이미지 분류(여러 라벨) → 속성(가림 · 잘림 · 난이도). 확대 · 이동, 단축키, 직전 이미지 라벨 복사, 박스 단위 그리드와 일괄 클래스 변경, 예측 깔아 두기 · 수락 | CVAT 도구 · 단축키, Lightly 박스 그리드, Label Studio 예측 |
| **3C 스마트 도구** | SAM 클릭 → 마스크 · 박스. 이미지 임베딩은 노드가 계산하고, 브라우저가 작은 디코더(ONNX Runtime Web)를 돌려 클릭마다 바로 반응하게 한다. Hub는 그대로 가볍다. 영상 · 시퀀스 트랙 보간은 시퀀스 항목이 생긴 뒤에 | CVAT AI 도구 |
| **3D 오토라벨** | (기존 Phase 3 계획) Labeler 플러그인(OVD → SAM → VLM 재확인 → SigLIP2 분류)과 등록한 모델로 예측, 신뢰도 라우팅(자동 승인 · 검수 · 폐기), 오토라벨 정밀도 리포트. 지금 걸러 낸 보기 전체에 돌릴 수 있고, 돌릴 노드는 0.37.0의 노드 고르기를 그대로 쓴다 | Lightly 플러그인 실행, ARCHITECTURE Annotate |
| **3E 검수 · 협업** | 검수(승인 · 거절 · 이미지 위 이슈), 겹쳐 라벨링과 작업자 간 일치도, 작업자별 진행 · 속도, 역할(라벨러 · 검수자 · 관리자) | CVAT 이슈, Label Studio 일치도 |
| **3F 큐레이션 연결** | Phase 2의 임베딩이 생긴 뒤: 임베딩 지도와 올가미 선택, 비슷한 이미지 · 텍스트 검색, 다양성 · 대표성 샘플링 → 태그 → 라벨링 묶음 | Lightly 지도 · 샘플링 |
| **3G 외부 도구** | CVAT · Label Studio 내보내기 · 가져오기. 이미 그 도구를 쓰는 팀을 위해 유지한다 | — |

**완료 기준**(기존 Phase 3 기준을 넓힘): 라벨 없는 1천 장 → 오토라벨 → 두 사람이 나눠 라벨링 · 검수 → 새 버전 → 학습. 정답 셋 대비 오토라벨 mAP와 작업자 간 일치도를 잰다.

## 6. 순서

| 순서 | 내용 | 버전 |
|---|---|---|

| 2 | 잘못된 라벨 찾기: 예측 저장, "라벨 의심 순", 예측 겹쳐 보기 · 라벨로 넣기 | 0.39.0 |

3G(외부 도구 연동)는 필요해질 때 어느 순서에든 넣는다.

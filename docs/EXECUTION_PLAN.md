# 실행 기반 계획 — 모델 템플릿 · 환경 · 저장 위치

0.5.0의 학습은 "Ultralytics YOLO를, 노드가 자동으로 만든 환경에서, 데이터가 있는 그 노드에서" 돌리는 한 가지 경우만 됐다.
이 문서는 그 세 고정값을 각각 고를 수 있는 것으로 바꾸는 계획이다.

**진행 상태**: 7장의 1단계(템플릿과 환경의 틀)는 0.6.0에 구현했다 — 모델 템플릿, 자동 설치·기존 환경, 새 학습 대화상자, 설정 메뉴.
0.7.0에 SDK(`badamoa_sdk`: 코드에서 설정 선언 + 진행 보고), 하이퍼파라미터 세부 설정, 두 번째 기본 제공 템플릿(torchvision 검출)을 더했다.
0.8.0에 분류(데이터 가져오기 · ImageFolder 변환 · 분류 지표 · torchvision 분류 템플릿)와 추적 확장의 일부(파일·이미지 기록, 패키지 목록, 잦은 기록 묶어 보내기)를 더했다.
Docker 환경, 평가·추론 진입점, 추적 확장(2.6), 저장 위치(4장)는 아직 계획이다.

| 지금 고정된 것 | 바꾸려는 것 | 장 |
|---|---|---|
| 학습 코드 = Ultralytics YOLO | **모델 템플릿**: 사내 학습·평가·추론 코드를 등록해 골라 쓴다 | 2 |
| 환경 = 노드가 자동 설치한 가상환경 | **환경**: 자동 설치 / Docker 이미지 / 서버에 이미 있는 환경 중에서 고른다 | 3 |
| 데이터 = 학습하는 노드의 디스크 | **저장 위치**: 노드 폴더 / NAS / 별도 데이터 서버 / S3, 등록과 학습 모두 | 4 |

원칙은 그대로다. Hub에는 ML 라이브러리가 없고, 기본 설치는 가볍고, 무거운 것(Docker, S3 라이브러리)은 쓰는 사람만 켠다.
그리고 **겉은 단순해야 한다**: 고를 수 있는 것이 늘어나도 일반 사용자의 화면은 늘어나지 않는다 (1.1).

## 1. 전체 그림

학습을 시작할 때 고르는 것이 네 가지가 된다.

```
릴리스 (무엇으로)  +  모델 템플릿 (어떤 코드로)  +  환경 (어디에 깔린 무엇으로)  +  노드 (어느 서버에서)
   └ 4장                └ 2장                         └ 3장                          └ 자동 또는 지정
```

- 템플릿을 고르면 그 템플릿의 **기본 환경**이 함께 선택된다. 바꿀 수 있다.
- 노드는 "그 환경을 쓸 수 있고 그 데이터를 읽을 수 있는(또는 받아 올 수 있는)" 서버 중에서 자동으로 정하거나 사람이 지정한다.
- 학습 실행(Run)은 네 가지를 모두 버전까지 기록한다: 릴리스, 템플릿 버전(코드 해시), 환경(이미지 다이제스트 또는 설치된 패키지 목록), 노드. "같은 설정으로 다시 실행"이 같은 코드와 같은 환경으로 돌아간다.
- 계보는 `모델 → 학습 실행 → (릴리스, 템플릿 버전, 환경)`으로 늘어난다.

### 1.1 화면 원칙 — 겉은 단순하게

이 문서의 나머지는 대부분 **안쪽 구조**다. 일반 사용자는 그것을 보지 않는다.
복잡한 것(마운트 경로, Docker 이미지, 자격 증명, 선언 파일)은 **관리자가 한 번 설정**하고, 사용자는 **이름을 고르기만** 한다.

| 하는 일 | 일반 사용자가 보는 것 | 보이지 않는 것 |
|---|---|---|
| 데이터셋 등록 | ① 저장 위치를 이름으로 고른다("연구실 NAS", "데이터 서버 1") ② 폴더를 눌러서 고른다 ③ 데이터셋 이름을 적는다 | 어느 노드가 읽는지, 마운트 경로, 버킷·자격 증명, 형식(자동 감지) |
| 학습 시작 | ① 릴리스 ② 모델(템플릿 이름과 크기) ③ epoch → **학습 시작** | 환경 종류(Docker인지 가상환경인지), 이미지 이름, 어느 서버인지, 데이터를 받아 오는지 |
| 진행 확인 | 한 줄 단계 표시: 대기 → 데이터 준비 → 환경 준비 → 학습 중(12/50) → 모델 등록 | 컨테이너·설치 로그 (펼치면 볼 수 있다) |
| 평가 · 추론 | 모델 화면의 "평가" · "테스트" 버튼과 릴리스 선택 | 어느 코드의 어느 진입점이 실행되는지 |

지킬 것:

1. **기본 화면에는 꼭 골라야 하는 것만 둔다.** 학습 대화상자의 기본 입력은 세 개다. 환경·노드·GPU 수·클래스 선택은 "세부 설정"에 접어 두고 기본값은 "자동"이다.
2. **경로를 타이핑시키지 않는다.** 저장 위치를 고르면 그 안의 폴더를 탐색해서 고른다. (지금의 가져오기 대화상자는 노드를 고르고 경로를 직접 적는데, 이 단계에서 바꾼다.)
3. **기술 용어는 관리자 화면에만 나온다.** 사용자 화면에는 Docker, 마운트, 버킷, venv 같은 말이 없고, 관리자가 붙인 이름이 나온다.
4. **기다림은 이유와 함께 보여 준다.** "환경을 준비하는 중입니다 (이 서버에서 처음 한 번, 약 3분)", "이미지를 받아 오는 중 3.2 / 12 GB", "빈 GPU를 기다리는 중 — ○○ 사용 중".
5. **실패는 할 수 있는 일과 함께 말한다.** "이 모델을 돌릴 수 있는 서버가 지금 없습니다. 관리자에게 '○○ 환경' 준비를 요청하세요." 원문 오류는 로그에 둔다.
6. **프로젝트 기본값.** 관리자가 프로젝트에 기본 모델·기본 저장 위치를 정해 두면 사용자의 대화상자에는 그것이 이미 골라져 있다.
7. **관리자 화면도 한 번에 끝나게.** 저장 위치·환경·템플릿을 등록하는 화면마다 "연결 확인" 버튼이 있고, 어느 서버에서 쓸 수 있는지를 바로 보여 준다.

관리자가 한 번 해 두는 것은 **설정** 메뉴 한 곳에 모은다: 저장 위치(이름 · 종류 · 서버별 경로 또는 버킷), 환경(이름 · 방식 · 이미지나 경로), 모델 템플릿(올리기 · 버전 · 기본 환경), 프로젝트 기본값.
소규모로 쓸 때는 이 설정이 전혀 없어도 된다: 내장 YOLO 템플릿과 자동 설치 환경, Hub 머신의 폴더가 기본으로 잡혀 있어 설치 직후 바로 등록하고 학습할 수 있다.

## 2. 모델 템플릿

### 2.1 무엇인가

**모델 템플릿 = 한 종류의 모델을 다루는 코드 묶음.** 학습·평가·추론·내보내기 진입점, 화면에 보일 설정 항목, 기본 환경을 한 파일에 선언한다.
예: "Ultralytics YOLO"(내장), "사내 RT-DETR", "불량 분류기".

지금의 Ultralytics YOLO도 같은 형식의 **내장 템플릿**으로 옮긴다. 내장과 사내 템플릿이 같은 경로로 실행되므로 특별 취급이 없다.

### 2.2 선언 파일

템플릿 폴더의 `badamoa.toml` 하나다 (TOML은 Python 표준 라이브러리로 읽으므로 의존성이 늘지 않는다).

```toml
name    = "inhouse-rtdetr"
title   = "사내 RT-DETR"
version = "1.2.0"
task    = "detect"            # detect | segment | classify
data_format = "coco"          # BADAMOA가 릴리스를 이 형식으로 풀어 준다: yolo | coco | imagefolder | manifest

[environment]
default      = "rtdetr-cu121"       # Hub에 등록된 환경 이름 (3장)
requirements = "requirements.txt"   # "자동 설치" 환경을 만들 때 쓰는 목록

[entrypoints]                 # 있는 것만 적는다. train만 있어도 된다
train   = "python train.py --config {config}"
eval    = "python eval.py --config {config}"
predict = "python predict.py --config {config}"
export  = "python export.py --config {config}"

[params.model]                # 학습 대화상자의 입력 항목이 된다
type = "string"
choices = ["r18", "r50", "r101"]
default = "r18"
label = "백본"

[params.epochs]
type = "integer"
default = 72
```

설정은 선언 파일 대신 **코드에서** 선언할 수도 있다(0.7.0, 2.6): `hp = bm.params(lr=bm.number(0.001, label="학습률", group="최적화", advanced=True))`.
Hub는 코드를 실행하지 않고 문법만 읽어 입력 칸을 만든다. 그래서 값은 직접 적어야 하고(변수·계산식 불가), 등록할 때 사내 코드가 Hub에서 실행되는 일이 없다. 같은 이름을 선언 파일에도 적으면 파일이 우선한다.
`advanced = true`인 설정은 "세부 설정"에 접히고, `group`은 그 안의 묶음 제목이다(학습 · 최적화 · 증강).

`data_format = "manifest"`는 변환 없이 이미지 경로·split·박스를 적은 JSON Lines 파일만 받는 방식이다. 자체 데이터 로더가 있는 코드용이다.

### 2.3 코드가 지켜야 할 약속

0.5.0에서 YOLO 스크립트에 쓴 약속을 그대로 일반화한다. 코드는 BADAMOA를 import하지 않는다.

| 방향 | 내용 |
|---|---|
| 입력 | `{config}` 자리에 JSON 파일 경로가 들어온다: 데이터 경로, 출력 폴더, 장치(`cpu` / `0` / `0,1`), 클래스 이름, 사용자가 고른 설정값. 평가·추론은 여기에 가중치 경로가 더해진다 |
| 진행 보고 | 표준 출력에 `@@badamoa {JSON}` 한 줄: `info`(라이브러리 버전·장치), `epoch`(epoch 번호와 지표) |
| 결과 | `result` 한 줄: 학습은 가중치 파일 경로·최종 지표·클래스별 지표, 평가는 지표, 추론은 예측 파일 경로 |
| 그 밖의 출력 | 전부 작업 로그가 된다 |

- 이 줄을 직접 찍을 필요는 없다. 한 파일짜리 SDK(`badamoa_sdk`, 의존성 없음)를 노드가 실행할 때 import 경로에 넣어 주고, 코드는 그 함수만 부른다 (2.6).
- 지표 이름은 자유지만 `map50_95, map50, precision, recall`(검출), `top1, f1`(분류)을 쓰면 표와 타일에 바로 나온다. 나머지는 그래프에 나온다.

### 2.4 등록과 전달

| 방법 | 동작 | 맞는 경우 |
|---|---|---|
| 올리기 | `badamoa template push ./my-trainer` — 선언을 검사하고 폴더를 묶어 Hub에 저장. 노드는 Hub에서 받아 해시로 캐시 | 기본. 노드가 Hub에만 닿으면 되므로 폐쇄망에서도 된다 |
| Git | 저장소 주소와 커밋을 등록. 노드가 직접 clone | 노드가 사내 Git에 닿을 때 |
| 이미지에 포함 | Docker 이미지 안의 경로를 지정 | 코드와 환경을 한 이미지로 굳혀 쓸 때 |

- `badamoa template init --task detect`가 뼈대(선언 파일, 약속을 지키는 `train.py` 예시, 보고 도우미)를 만들어 준다.
- 올릴 때마다 **버전**이 쌓이고, 학습 실행은 쓴 버전의 코드 해시를 기록한다. 같은 버전 번호로 다른 코드를 올리면 거부한다.
- 화면: Develop 아래 **템플릿** 목록(이름 · 태스크 · 버전 · 지원 진입점 · 기본 환경 · 이 템플릿으로 만든 모델 수).

### 2.5 평가·추론·내보내기에 쓰이는 방식

모델 버전은 **자신을 만든 템플릿 버전을 기억한다.** 그 모델을 평가·추론·내보낼 때는 같은 템플릿의 진입점을 쓰므로, 학습 코드와 추론 코드의 전처리가 어긋나지 않는다.

| 진입점 | 작업 | 결과가 가는 곳 | 시기 |
|---|---|---|---|
| `train` | 릴리스 → 가중치 | 학습 실행, 모델 버전 | 1C |
| `eval` | 모델 + 릴리스(split) → 지표 | 모델의 **평가 기록**. 서로 다른 데이터로 학습한 모델도 같은 릴리스로 평가해 공정하게 비교 | 0.9.0 |
| `predict` | 모델 + 이미지 묶음 → 예측 | 샘플 테스트 화면(0.9.0). 라벨 개정(`autolabel:<모델>@<버전>`)으로 저장하는 것은 Phase 3 | 0.9.0 · Phase 3 |
| `export` | 모델 → ONNX · TorchScript (TensorRT는 GPU 서버에서) | 모델의 내보낸 파일 | 0.9.0 |

진입점이 없는 기능은 그 모델에서 버튼이 비활성으로 보인다("이 템플릿에는 평가 코드가 없습니다").

### 2.6 추적 — W&B·MLflow처럼 붙인다

사내 코드를 붙이는 사람이 이미 아는 방식이어야 한다. W&B나 MLflow를 쓸 때처럼 **코드에 몇 줄을 넣으면 그 정보가 실시간으로 화면에 나온다.**

```python
import badamoa_sdk as bm                    # BADAMOA가 실행할 때 자동으로 제공. 설치하지 않는다

hp = bm.params(                             # 설정 선언 → 학습 대화상자의 입력 칸 (wandb.config)
    epochs=bm.integer(30, min=1, label="epoch"),
    lr=bm.number(0.001, label="학습률", group="최적화", advanced=True),
)
run = bm.init()                             # 실행 시작. 데이터·출력 폴더·장치
for epoch in range(1, hp.epochs + 1):
    ...
    bm.log({"train_loss": loss, "map50_95": score}, step=epoch)   # 지표 → 그래프
    bm.progress(epoch, hp.epochs)                                  # 진행률
bm.log_model(run.out / "best.pt")           # 모델로 등록할 가중치
bm.finish({"map50_95": best})               # 최종 지표
```

| 하려는 일 | W&B | MLflow | BADAMOA | 상태 |
|---|---|---|---|---|
| 실행 시작 | `wandb.init()` | `mlflow.start_run()` | `bm.init()` | 0.6.0 |
| 설정(하이퍼파라미터) | `wandb.config` | `log_params` | `bm.params(lr=bm.number(…))` — 코드에 선언하면 화면의 입력 칸이 되고, 고른 값이 `hp.lr`로 들어온다 | 0.7.0 |
| 지표 기록 | `wandb.log({...}, step=)` | `log_metric(s)` | `bm.log({...}, step=)` — 어떤 이름이든 그래프가 생긴다 | 0.6.0 |
| 진행률 | (없음) | (없음) | `bm.progress(현재, 전체)`, `bm.epoch(...)` | 0.6.0 |
| 모델 등록 | `log_artifact(type="model")` | `log_model`, `register_model` | `bm.log_model(파일)` → 모델 화면에 버전으로 | 0.6.0 |
| 끝내기, 최종 지표 | `wandb.finish()`, `run.summary` | `end_run()` | `bm.finish({...})` | 0.6.0 |
| 콘솔 출력 | 자동 수집 | — | 자동: `print`가 그대로 실시간 로그 | 0.5.0 |
| 실행한 코드 버전 | Git 커밋 | Git 커밋 | 자동: 템플릿 버전과 코드 해시 | 0.6.0 |

W&B·MLflow와 다르게 한 것:

- **네트워크도 키도 쓰지 않는다.** 도우미는 표준 출력에 한 줄을 찍을 뿐이고, 그것을 Hub로 보내는 일은 노드가 한다. 그래서 가상환경·Docker·기존 환경 어디서나 같은 코드가 돌고, 폐쇄망에서도 되고, BADAMOA 밖에서 그냥 실행해도 문제없다.
- **실행을 만드는 쪽이 반대다.** W&B는 코드가 실행을 만들지만, 여기서는 화면(또는 에이전트)이 실행을 만들고 설정을 코드에 넘긴다. 그래서 설정이 코드에 흩어지지 않고, "같은 설정으로 다시 실행"과 대기·GPU 배정이 된다.
- **모델까지 한 흐름이다.** 기록한 가중치가 곧 모델 버전이 되고 릴리스·템플릿 버전·환경과 묶인다.

W&B나 MLflow에 **함께** 기록하고 싶으면 코드에서 그것을 그대로 불러도 된다. BADAMOA 쪽 기록을 그쪽으로 복제하는 미러는 "필요해지면" 목록에 있다.

### 2.7 기본 제공 템플릿

"Ultralytics만 되는 도구"가 아니다. 기본 제공 템플릿은 사내 템플릿과 같은 형식이고, 오픈소스 모델을 하나씩 같은 방식으로 더한다.

| 템플릿 | 모델 | 태스크 | 상태 |
|---|---|---|---|
| `yolo` | Ultralytics YOLO11 · YOLO26 | 검출 | 0.5.0. 하이퍼파라미터 24개를 세부 설정으로 (0.7.0) |
| `torchvision` | Faster R-CNN · RetinaNet · FCOS (ResNet-50 백본), Faster R-CNN · SSDlite (MobileNetV3) | 검출 | 0.7.0. SDK로 작성한 참고 예시이기도 하다 |
| `classify` | ResNet · EfficientNet · MobileNetV3 · ConvNeXt · RegNet · ViT · Swin (torchvision) | 분류 | 0.8.0. 혼동 행렬 그림을 실행에 기록 |
| 그 밖의 검출 | RT-DETR, D-FINE, RF-DETR | 검출 | 계획 (Phase 4) |
| `yolo-seg` | Ultralytics YOLO11-seg · YOLO26-seg | 분할 | 0.11.0. Mask R-CNN 등은 계획 |

**분류(ResNet 등)**는 0.8.0에 들어갔다. 모델보다 데이터 쪽 일이 많았다: 카탈로그가 박스 라벨만 알았기 때문이다.
분류 템플릿을 넣는 데 ① 분류 데이터 가져오기(폴더 이름 = 클래스) ② 이미지당 클래스 라벨을 개정으로 저장하고 화면에 표시
③ 릴리스 → ImageFolder 형식 변환 ④ 분류 지표(top-1 · F1)를 표와 타일에 표시가 필요했다. 분류 라벨은 위치가 없는 `[클래스]` 하나로 저장해 기존 표와 필터를 그대로 쓴다.

기록 빈도가 높을 때(0.8.0): 노드가 약 1초 단위로 묶어 Hub에 보내고, step이 1,200개를 넘는 지표는 읽을 때 600개 안팎으로 간추린다. iteration마다 기록해도 학습이 느려지지 않는다.

## 3. 환경

### 3.1 세 가지 방식

| 방식 | 선언 | 실행 | 맞는 경우 |
|---|---|---|---|
| 자동 설치 (지금) | 패키지 목록 | 노드가 처음 쓸 때 uv로 가상환경을 만든다. PyTorch는 드라이버에 맞는 빌드 | 준비 없이 바로, Windows 노드 |
| Docker 이미지 | 이미지 이름·태그 | 노드가 컨테이너로 실행. 배정받은 GPU만 넘기고 데이터·작업 폴더를 마운트 | 환경을 고정해 여러 서버에서 똑같이, 폐쇄망 |
| 기존 환경 | 서버에 있는 Python 경로 (conda·venv) | 그 Python으로 실행 | 이미 잘 돌아가는 환경이 서버에 있을 때 |

환경은 Hub에 **이름으로 등록**하고(예: `yolo-auto`, `rtdetr-cu121`), 템플릿은 기본 환경의 이름만 가리킨다. 환경과 코드가 따로 버전을 가지므로 같은 코드를 다른 환경에서 돌려 볼 수 있다.

### 3.2 노드와의 관계

- 환경마다 **어느 노드에서 쓸 수 있는지**가 표시된다: 준비됨 / 준비 가능(이미지를 받거나 설치하면 됨) / 불가(OS가 다름, Docker 없음).
- "미리 준비" 작업을 둔다. 첫 학습이 설치나 이미지 받기를 기다리지 않게 한다.
- 스케줄러는 환경을 쓸 수 있는 노드에만 배정하고, 대기 사유에 "이 환경을 쓸 수 있는 노드가 없음"을 표시한다.
- 기존 환경은 노드마다 경로가 다를 수 있으므로 노드별로 경로를 적는다.

### 3.3 Docker 방식에서 처리할 것

- GPU는 `CUDA_VISIBLE_DEVICES` 대신 컨테이너에 넘기는 장치 목록으로 제한한다.
- 학습 데이터는 원본을 가리키는 링크이므로, 원본 폴더도 같은 경로로 읽기 전용 마운트한다.
- 컨테이너 안의 사용자를 노드 사용자로 맞춰 결과 파일의 소유자가 root가 되지 않게 한다.
- 취소는 프로세스 종료가 아니라 컨테이너 중지로 한다.
- 실행 기록에 이미지 다이제스트를 남긴다.
- Linux 노드 전용이다 (Docker + NVIDIA Container Toolkit). Windows 노드에서는 선택지에 나오지 않는다.

## 4. 저장 위치

### 4.1 등록

등록은 방식과 상관없이 "그 데이터를 읽을 수 있는 노드가 훑어서 해시·크기·라벨·썸네일만 Hub에 올린다"이다. Hub는 이미지 파일을 받지 않는다.

| 위치 | 등록하는 노드 | 추가로 적는 것 | 상태 |
|---|---|---|---|
| 노드 폴더 | 그 서버 | 없음 | 됨 (0.4.0) |
| 별도 데이터 서버 | 데이터 서버에 설치한 노드 (GPU 불필요) | 없음 | 등록은 됨 |
| NAS | NAS를 마운트한 아무 노드 | 서버별 마운트 경로 | 계획 |
| S3 호환 | 버킷에 닿는 아무 노드 | 버킷·경로·자격 증명 | 계획 |

S3는 등록할 때 모든 객체를 한 번 내려받아 해시와 썸네일을 만든다(저장하지 않고 버린다). 이미지를 내용 해시로 식별하기 때문이다.

### 4.2 학습할 때 읽기

학습 노드는 이미지마다 아래 순서로 읽을 곳을 찾는다.

1. 내 디스크에 등록된 폴더 → 그대로 (지금 방식)
2. 내가 마운트한 NAS → 내 마운트 경로로 바꿔서. 복사 없음
3. 내 캐시 → 전에 받아 둔 것. 해시로 식별하므로 다시 받지 않는다
4. 없음 → S3에서 직접 받거나, 데이터 서버에서 Hub를 거쳐 받아 캐시에 넣는다

- 노드는 Hub로 나가는 연결만 쓰므로 서버 간 전송은 **Hub를 거친다.** 수백 GB 데이터는 Hub의 네트워크 속도에 묶이니 NAS나 S3가 맞다. 서버 간 전송은 그런 인프라가 없을 때의 방법이다.
- 캐시는 노드별 용량 한도를 두고 오래 안 쓴 것부터 지운다.
- 학습 노드 선택: 바로 읽을 수 있는 노드 → 캐시에 가장 많이 가진 노드 → 그 밖의 GPU 노드 순으로 고르고, 받아 와야 하는 양을 시작 전에 보여 준다.

## 6. 권한

사내 코드를 등록한다는 것은 노드에서 임의의 코드를 실행한다는 뜻이다.

- 템플릿·환경·저장 위치의 등록과 수정은 **관리자**만 한다. 멤버는 등록된 것을 골라 쓴다.
- 등록·수정·사용은 모두 감사 로그에 남는다.
- S3 자격 증명과 레지스트리 자격 증명은 Hub에 저장하고, 그것이 필요한 작업에만 넘긴다. 화면과 로그에는 나오지 않는다.
- 자동 설치·기존 환경 방식의 코드는 Node Agent를 실행한 사용자 권한으로 돈다. 격리가 필요하면 Docker 방식을 쓴다.

| **4** 서버 간 동기화 | 노드 캐시, Hub 경유 전송, 받아 올 양 미리 표시, 캐시 한도 | 데이터 노드와 학습 노드를 따로 띄워 학습 | 가능 |
| **5** Docker 환경 | 3.3의 항목 전부, "미리 준비" 작업 | Linux GPU 서버에서 공식 Ultralytics 이미지로 학습 | 불가 — Linux 서버 검증과 함께 |
| **6** S3 | 버킷 등록, S3에서 등록과 학습, 자격 증명 보관 | MinIO 또는 실제 버킷 | 엔드포인트가 있어야 함 |

`predict`와 `export` 진입점은 형식만 1단계에서 정해 두고, 실제로 쓰는 Phase 3(오토라벨)·Phase 4(내보내기·추론)에서 구현한다.

순서의 이유: 1은 2~6이 모두 기대는 틀이고(환경 선택과 템플릿이 같은 실행 코드를 고친다), 2는 1 위에서 작고 "모델 비교가 공정하지 않다"는 지금의 한계를 없앤다. 3·4는 이 PC에서 확인할 수 있고, 5·6은 외부 자원이 있어야 확인할 수 있어 뒤에 둔다.

## 8. 만들지 않는 것

- 템플릿마다 다른 화면. 설정 항목은 선언에서 자동으로 만든 입력 폼 하나다.
- 템플릿 마켓·공유 저장소. 사내용이므로 Hub에 올린 것이 전부다.
- 자체 이미지 빌드. Docker 이미지는 밖에서 만든 것을 이름으로 가리킨다.
- 노드끼리 직접 전송. 먼저 Hub 경유로 만들고, 속도가 문제가 되면 그때 추가한다.

## 9. 정해야 할 것

- 사내 학습 코드가 지금 어떤 형태인가 (스크립트 몇 개 / 설정 파일 기반 프레임워크 / 노트북). 2.3의 약속에 맞추는 데 드는 수정량이 달라진다.
- "미리 정해진 환경"이 Docker 이미지인가, 서버의 conda 환경인가. 뒤쪽이면 1단계만으로 쓸 수 있다.
- NAS·S3가 실제로 있는가. 없다면 5·6단계는 코드만 넣고 확인이 미뤄진다.
- 템플릿을 등록할 수 있는 사람을 관리자로 한정해도 되는가.
